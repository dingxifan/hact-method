# foundation-review 证据化收紧（G1 探针通用化 + G2 自绿复现化）

> 设计稿 · 2026-07-12 · 收紧现有 foundation-review 门、非新增机制（与 2026-07-08 机制冻结相容）
> 触发：doc-extract V0 走骨架完整跑通后二轮独审（Codex 独立对抗复核）暴露"声明档 > 实测档"。

## 一、病根（实证驱动，非理论推演）

doc-extract V0 走骨架的两轮独审对比给出一条干净证据链：

- **一轮 foundation-review**（跑在默认模型上）签"通过·0 阻断"，把五类**非安全构造级洞**判为无发现/建议：`RawFieldValue` 结构类型可绕、HTTP 单例 `window.fetch` 可绕、`registry_record` 原地覆盖 DB 未挡、状态机合法边裸 SQL 可绕、router 外壳可加顶层路由不红。
- **二轮 Codex**（`second-review-prompt.md`）判同一批为**阻断**。

两轮唯一的结构性差别 = 二轮提示词强制「**判构造级前必须亲手写一条绕过的违规反例、跑检查验证它真被挡**」。一轮走的是"读代码判断像不像挡得住"。

**结论**：对"声明档 > 实测档"这类漏判，**brief 的严苛度 > 模型大小**（一轮默认模型也漏了 = 不是模型能力问题，是审查方法问题）。现有 `foundation-review.md` 已有执行化反例要求，但**只绑定了安全项**（数据隔离/鉴权/越权），非安全构造级声明走的是"读代码反推"——正是漏判滑过的那一格。

## 二、三个缺口与本轮取舍

| # | 缺口 | 处置 |
|---|---|---|
| **G1** | 执行化反例只绑安全项；非安全构造级声明只被"读代码反推" | **本轮做**——探针要求通用化到每个 ≥机械级声明 |
| **G2** | 自绿被按面值采信（只问"全绿吗"），无干净环境复现要求、无"仓库不可移植 vs 审查环境特性"区分 | **本轮做**——自绿复现化 |
| **G3** | 机械级"接线"含糊：配置里有规则就算，还是必须接进真在自动跑的门（CI/pre-commit）？ | **搁置记待议**——纯残余 = "必须另有常驻 CI"= 新增基建要求 = 撞冻结；且 G1+G2 已吸收大半（规则有洞→G1 撞、检查没跑→G2 暴露）；真正价值随第五阶段真人 push 上升（真人 commit 不走 develop 自绿），与决策#24"团队引入期恢复人工 merge 门"同一时点重评 |

## 三、落点（净：动一份运行时文件 + 一条账本注 + 记账）

**改动 A — `templates/review-briefs/foundation-review.md` · G1**
- "实测档怎么判"块：把"亲手写可达反例"从安全项**升为对每个 ≥机械级构造级声明通用**——判构造级前写绕过代码、跑对应检查（类型边 tsc / lint 边 eslint·stylelint / DB 不变式裸 SQL / 框架守卫加匿名·越权路由），被挡=成立，退出 0 或 SQL 成功=实测档<声明=阻断；别名导入 / 替代全局出口 / 结构类型赋值绕 excess-property / 裸 SQL 走合法边等**绕过形态都要试到**（写成栈无关的形态清单，不写项目具体类型名——守决策#27）。
- **保留**安全项"可达性"附加判据（上游闸/跨层 RLS 可能使反例不可达→不算阻断，JHH 教训不丢）。
