# G4 低重复执行与 Standards 收缩

> 日期：2026-09-04
> 边界：只改方法论模板与规范；不分发任何项目仓，不降低独立审查、固定 diff 或最终全量验证。

## 交付项

| 项目 | 状态 | 验收 |
|---|---|---|
| 单人 wave | ✅ | 仅满足条件时由用户在 G4 编排阶段选择；仍逐包实现、固定快照和独审，末端只跑一次 |
| 复用查询分流 | ✅ | 小而明确的登记表由执行单元直读；跨模块盘点才派只读调查单元 |
| 视觉规格切片 | ✅ | 前端只读全局基线和任务包点名的页面规格；存量无稳定锚时回退全文 |
| Standards 消耗审计 | ✅ | full review 留实际核过的规则 id；G2 维护时按近两期真实引用与 enforcement 清除无效残量 |

## 不变量

1. `交付=串行/可并行` 仍表达共享写集与团队协作边界，不被 wave 改写。
2. wave 中每个任务仍有自己的 freshness preflight、fixed diff、full/targeted 独审与 finding 路由。
3. Standards 不取代 PRD/TRD/design/Foundation/check/test 的权威职责。
4. 模型档位与并行检测命令须以真实项目对照数据决定，本轮不虚构通用结论。
