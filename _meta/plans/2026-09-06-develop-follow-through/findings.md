# 设计依据与验证

## 诊断边界

尚无用户历史停顿会话记录，不能把批次结束硬边界断言为实际根因。本轮针对源码可证实的协议缺口：阶段汇报缺少接续约束、escape-hatch 与失败重派顺序冲突、结束声明早于 feedback、恢复记录缺当前阶段/待接收单元/下一动作。

待议清单仅核与本轮相关的「hotfix 前端设计门减重」「独审 loop 三轮封顶后处置」：两者不在本轮改造中放宽或结项。wave 规则保持现状，自动清空同层队列押后。

## 取舍

- 规则放共同 develop 正文，默认适用于已授权任务集，无需依赖个人 skill 再次触发。
- blocked 由主线核对证据与授权后分类；可恢复的信息/执行故障先补证，真实人类边界直接升级。
- 使用既有 task progress；wave 的机械 JSON 不加字段，补充信息写当前任务 progress，避免破坏既有校验。
- 反馈收尾后才能宣告完成；合并后不再利用「小于五行」旁路追加未经独审/验证的代码。

## 验证

### 实际执行的检查

- `node scripts/check-paths.js`：128 个运行时文件，0 个绝对路径命中。
- `node _meta/scripts/check-runtime-neutral.js`：通过。
- `node templates/scripts/check-sprint.worktree.test.js`：正反夹具通过。覆盖旧接口保持严格、显式本轮未暂存 progress 放行、其他任务/未知 task/path traversal 拒绝、已跟踪更新、多任务、暂存拒绝、目录拒绝、未通过审查/未审修改/stash 不被豁免。
- `node templates/scripts/review-profile.integration.test.js`：12/12，通过真实固定 diff 的审计链核验。
- `node templates/scripts/wave-split.transaction.test.js`：真实 Git/worktree 拆分恢复夹具通过。
- `git diff --check`：通过。

增加目录负例时首次实测失败：已有 `exists()` helper 只认普通文件，使目录被误当缺失路径。改用 `lstatSync` 判路径类型后该负例翻红（检查器 exit 1），整组测试通过。未增加任何项目状态或 wave schema 字段。

### 场景走查（本会话静态规则核验）

| 输入场景 | 按新规范得到的动作 | 核验落点 |
|---|---|---|
| 实现返回 done、尚无独审 | 核实产物，固定 tree 并立即派审，不宣布完成 | 主线接续协议 / 阶段 B |
| 首轮有授权内 fix-code | 重派整改，随后 targeted；不要求“继续” | 主线接续协议 / finding 路由 |
| 同一根因三轮仍阻断 | 转 revise-doc 或人工裁决，换单元不清零 | escape-hatch / 失败协议 |
| 审查运行时问“现在呢” | 回答真实阶段后接收结果继续，不重复派发 | 主线接续协议 |
| 用户明确暂停 | 核本轮活跃单元，安全中断或记录影响后交接 | 结束判据 |
| 测试静默/工具中断 | 核进程、保存证据，不冒充通过或并发重跑 | escape-hatch |
| 子单元未读仓内已有答案 | 主线补权威输入，在现有额度内恢复/重派 | escape-hatch / 失败协议 |
| 必需设计、契约、权限或敏感裁决缺失 | 停在对应边界，给证据与所需人类动作 | escape-hatch / 原人工门 |
| individual 第一包已合并、集合还有第二包 | 切回合法基线继续下一包，不触发集合完成声明 | 结束判据 / 主循环 |
| PR 已合并但状态/反馈未收尾 | 核 PR 后仅补剩余记录，不重复实现或创建 PR | 断点续做 |
| wave 中当前任务被阻断 | 保留整组恢复，不凭普通 progress 单独释放任务 | escape-hatch / 上下文管理 |
| progress 写“审查通过”但 tree 已变化 | 以固定报告和实际 diff 对账，按影响复验 | 断点续做 |

上述场景均能在规则中找到对应接续或暂停路径。这是文本协议核验，不是独立审查，也不是模型行为实验。真实项目后续应记录“已授权下一动作存在时是否仍提前结束”，并区分必要人工门与过早停止；本轮未宣称已降低实际停顿率。
