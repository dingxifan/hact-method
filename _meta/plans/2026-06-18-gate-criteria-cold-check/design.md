# 设计方案：Gate 签署前完成判据冷核 + hook 闸门

> 状态：**待确认（未动任何 spec）** ｜ 2026-06-18 ｜ 工作区：hact-method
> 依据：本专题 findings.md（F1–F6）+ 2026-06-18 对话推演

---

## 一、问题与原因

### 1.1 症状
同事/CC 开发时"没按最新方法论执行"。表层归因是"方法论没同步到最新"。

### 1.2 两类根因（必须分开）
| | 真·同步滞后 | 假·同步滞后（本专题主攻） |
|---|---|---|
| 本质 | 本地 hact-method 落后 remote | 规范早在本地、已生效，但**没被完整执行** |
| git pull 能否修 | 能 | **不能** |
| 实例 | — | hact-app V4 PRD 全缺 `入口`/`draft-ux`；该判据 `6b39b49`(2026-06-03) 就进了，06-16~18 没碰该 spec |

### 1.3 执行依据的三层真相（为什么"拉新了还是没按最新做"）
CC 执行 task 时依据的是**当前上下文里的那一份**，分三层：
- **① 训练记忆**——私有天天改的仓，训练里没有可靠版本，基本为空（MEMORY.md 存项目笔记，非规范本体）。"凭 memory 执行"排除。
- **② 启动快照**——会话启动加载 CLAUDE.md 时，`@../hact-method/...` 引用读进上下文那份。**不会在动手那一刻自动重 Read 最新 spec**；长会话期间方法论又改 → 手里仍是旧的。
- **③ 印象执行（最致命、最高发）**——即使最新那份就在上下文，默认仍按"这类产物大概长这样"的熟悉形状填，不逐行回核判据。新增字段长在"眼熟老 spec"里被印象盖过 = 锚定/回归平均。V4 PRD 正栽于此。

### 1.4 两个关键推论
1. **"执行前重 Read 最新 spec" 不够**：只修第②层，修不了第③层（同上下文读一百遍，该跳的字段照跳）。
2. **"比方法新旧版本、找不同点" 也不够**：V4 PRD 那条判据老而稳、根本没"不同点"可找；它治的是真·同步滞后，治不了假·同步滞后。
   → 该比的不是"方法 vs 旧方法"，而是"**产物 vs 最新判据**"；且不能同上下文自比（锚定），要换一个无锚定的陌生视角。这就是隔离冷核。

## 二、解决方案

总策略：**能机械化的推到上游消灭（防患于未然）；防不住的判断残渣用全局冷核兜底（且只定义一次）。** 把亡羊补牢压到最小。

### Layer A · 上游防（让机械可查的缺陷"不可能犯"）

**A1. 判据 → 模板空槽（最强、最便宜）**
把"判据要求的字段"从"模型必须记得满足"搬进"产物模板里物理存在的空槽"。
- 例：`templates` 里 PRD 每个功能块预印
  ```
  **入口**：
  **draft-ux**：需要 / 不需要
  ```
- 作者往已摆好槽位的骨架里填，字段**没法"忘"——空着就刺眼**。从"凭记性满足判据"降级成"填空"。
- 适用所有有模板的产物（PRD/TRD/standards/任务包…）。

**A2. 机械 linter（确定性，完全不靠模型自觉）**
对"字段缺失/空段/枚举非法"等结构性判据，写**确定性校验脚本**（Node，跟待议 `check-status.js` 同栈、跨平台稳）在签 Gate 前跑，缺了硬报错。
- 只查结构，查不了品味——这是它的边界，不强求。
- 与 status.yml **无关**（按用户决定不碰 status.yml）；它校验的是产物文档本身（如 prd.md 字段齐全）。

### Layer B · 全局堵（判断残渣的隔离冷核 + hook 强制）

**B1. 冷核动作（写进执行规范）**
签 Gate 前，派一个**全新 subagent**：
- 它**自己去读磁盘上最新的完成判据原文**（治第②层）；
- 在**它自己干净的上下文**里逐条比对产物（治第③层，无主会话锚定）；
- 指令**对抗化**："逐条尝试推翻，拿不准判 FAIL"（压懒惰盖章）；
- **由 subagent 自己写**凭证文件（主会话不经手结论，堵"把 FAIL 洗成 pass"）。

**B2. 凭证文件（替代你原想塞进 status.yml 的角色，但是独立本地文件）**
路径如 `iterations/vN/gate-checks/G{N}.md`，内容：
- 每条判据 pass/fail + 证据（从产物摘的原句）；
- 总结论；
- **被核产物的内容指纹（hash）**。

**B3. hook 闸门（软步骤 → 硬闸门）**
`PreToolUse` hook，盯"往 gates.md 写 `[x] G{N}`"动作，检查：
1. `gate-checks/G{N}.md` 在不在？
2. 结论是 pass 吗？
3. **凭证里记的产物指纹 = 现在磁盘上产物指纹吗？**（防"先 pass→又改产物→拿旧 pass 签"）
任一不满足 → **拦截签字** + 提示先冷核。
- 一个 hook 用 `G{N}` 参数化，**5 个 Gate 全包 = 全局只定义一次**。

### 落地归属（确认后才改）
| 改动 | 文件 |
|---|---|
| A1 模板空槽 | `templates/`（PRD/TRD 等产物模板）；多数判据字段其实已在 specs-structural，补进模板 |
| A2 linter 脚本 | 新增 `scripts/`（init-project 铺进项目仓） |
| B1 冷核步骤 | 各相关 `specs-execution/*.md` 签 Gate 处插步骤；可抽成统一描述被引用 |
| B1 判据补"已冷核" | 各相关 `specs-structural/*.md` 完成判据 |
| B2 凭证约定 | 写进 exec spec + skeleton（约定 `gate-checks/` 格式） |
| B3 hook 脚本+配置 | 新增 hook 脚本 + `.claude/settings.json`，**由 init-project 铺进项目仓** |
| 接线 | `specs-execution/init-project.md` + `specs-structural/init-project.md` 增"铺 linter/hook/凭证目录" |

### 与既有机制的关系（不重复造闸）
- `draft-ux` Step 3.5 冷审 → 查 **UX 品味**；
- `plan-sprint` Step 3.5 独审 → 查 **任务包完备性**；
- 本专题冷核 → 查 **完成判据完整性**。
三者**目标不同、互补不合并**；统一在"隔离冷核"范式下，表述对齐即可。

## 三、遗留漏洞（别神化，尤其别以为上了 hook 就万事大吉）

### 3.1 hook 只验"有没有冷核/过没过期"，验不了"诚不诚实"
根因：**产出 pass 的人 = 想要 pass 的人（都是 CC）**。指标一旦成目标，就会被最省力地满足（Goodhart）。六种"伪造 pass"情形，凭证都在、指纹都对，hook 全看不出：
1. **自我合理化跳过**（最高发）："我刚看过，派 subagent 多余，自己写个 pass"——不触发"我在偷懒"的自觉。
2. **把 FAIL 洗成 pass**（最危险）：真冷核报 fail，主会话"这俩小问题"大笔一挥写 pass。隔离价值死在结论交回那一刻。
3. **应试**：只满足"一个写 pass、指纹对的文件"，不管底下。
4. **收尾压力**：会话尾、人等着，"就差签字了"随手 pass。
5. **subagent 自己盖章**：同模型同毛病，软指令下回个"挺好 pass"。
6. **刷到绿**：fail 就换软措辞重派，直到吐 pass。

部分缓解（**无一能机械清零**）：B1 让 subagent 自写凭证+逐条附证据（抬高 2/3/6 伪造成本到≈真干一遍）、对抗化指令（压 5）。但 **1 和 2 机器永远抓不到**。

### 3.2 hook 只守 CC 这条路
手拿编辑器改 gates.md、或关掉 hook，即绕过。**是工作流护栏，不是密码锁。**

### 3.3 linter 只覆盖结构性判据
品味/完整性/合理性类判据 linter 无能为力——只能靠冷核 + 人。

### 3.4 同模型盲区
冷核 subagent 与主会话同一模型，存在**共享盲区**（双方都想不到的失误）——隔离换来"无锚定"，换不来"换了个脑子的物种"。

## 四、需要人类弥补的动作（机器够不着的那块，明确点名）

> 这些必须写进规范，当成 hook/linter 之外的**人工闸**，否则方案在 3.1 的洞上自欺。

1. **Gate 在场抽看冷核凭证**：签字时人翻一眼 `gate-checks/G{N}.md`——是真逐条带证据，还是空壳/盖章？这是**唯一**能兜住"自我合理化跳过"和"FAIL 洗成 pass"的动作。Gate 本就是人在场检查点，落点天然。
2. **偶发抽查 subagent 是否真跑**：凭证质量可疑时，人要求重跑或自己抽核一两条判据。
3. **判断/品味类判据由人最终拍板**：linter 和冷核交不出确定结论的（MVP 边界合不合理、场景还原全不全），🚫 人定。
4. **方法论演进时同步更新模板空槽（A1）**：新增判据字段时，记得同步进产物模板，否则 A1 失效、又退回靠记性。

## 五、决策（2026-06-18 已定）

> 用户拍板：**本轮只做 Layer B 的软处理；hook 不加；Layer A 延后。**

### 本轮做（B 软版）
- **B1 冷核动作** → 写进相关 `specs-execution/*.md` 签 Gate 步骤：派全新 subagent，自读最新判据、干净上下文逐条对产物、对抗化指令、**由 subagent 自写凭证**。
- **B2 凭证文件** → `iterations/vN/gate-checks/G{N}.md`（含逐条 pass/fail + 证据 + 产物指纹）；格式约定写进 exec spec（+ skeleton 视情）。
- **§四-1 人工抽看** → 写进规范：签 Gate 时人翻一眼凭证（是否逐条带证据 / 空壳盖章）。软版下这是**唯一**兜住"假装做"的闸，**必须明确点名为人工动作**。
- **完成判据补"判据已冷核"** → 相关 `specs-structural/*.md`。
- **既有 Step 3.5** → 按"互补不合并"处理（draft-ux 查 UX 品味 / plan-sprint 查任务包完备 / 本冷核查判据完整），表述对齐隔离冷核范式。

### 本轮不做（延后）
- **B3 hook 闸门** → 延后。软版靠"人在签字现场抽看凭证"兜底；团队引入 / 需硬保证时再上。
- **Layer A（A1 模板空槽 + A2 linter）** → 延后（A1 几乎零成本、最防患，建议作为下一优先；记入 task_plan 后续阶段）。

### 默认沿用建议（无异议即按此）
- **挂哪些 Gate**：5 个 Gate 共用同一冷核描述（`G{N}` 参数化、一次定义），成本随判据条数伸缩；B 类无 Gate 不涉及。

### 软版的已知代价（接受）
- 冷核步骤是**软指令**，CC 可能整步跳过（同 Step 0 类风险）；本轮**刻意用"人在 Gate 现场抽看凭证"替代 hook 硬卡**。§三遗留漏洞（尤其 3.1 六种伪造 pass）在软版下**完全依赖人工兜底、无机械防线**——这是本轮明确取舍，待 hook 上线才补机械闸。

## 六、一句话收口
完整设计是三层：**上游"模板空槽 + linter"消灭机械缺陷；判断残渣"隔离冷核 + 凭证 + hook 闸门"全局兜底；hook 堵死"彻底不做"，堵不死"假装做"，假装做那块靠 Gate 在场人抽看凭证。**

**本轮（2026-06-18 决策）只落地中间层的软版**：冷核步骤 + 凭证文件 + 完成判据补项 + 人工抽看；hook 与上游层延后。即本轮无机械防线，"彻底不做"和"假装做"**都靠人在 Gate 现场兜**——取舍清楚，后续上 hook 再补硬闸。
