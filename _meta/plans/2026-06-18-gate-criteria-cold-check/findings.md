  - `每个功能已标记是否需要 draft-ux（含新页面或多分支交互流程的功能必须标记 需要）`

- 结论：规范本地从 06-03 就在、已生效；缺字段是**起草 V4 PRD 时没把完成判据跑完**，与本地是否拉新无关。git pull 一百遍也修不了。

## F2. 两类根因必须分开（本专题只打第 2 类）

| | 真·同步滞后 | 假·同步滞后（本专题） |
|---|---|---|
| 本质 | 本地 hact-method 落后 remote | 规范已在本地、已生效，但没被完整执行 |
| git pull 能否修 | 能 | **不能** |
| 典型误诊 | — | 感觉输出不对 → 归咎"没同步" → 去 pull → 啥也没变 |
| 解法 | 改造 Step 0（去 `2>/dev/null`、校验 master 分支、真实前后对比） | **Gate 前冷核完成判据**（本专题） |

> 第 1 类（Step 0 静默失败）的分析见本次对话；是否同期改，列为开放问题 5。

## F3. 为什么"已生效规范"会被静默跳过（机理）

1. **增量改老规范最易被吞**：draft-ux 字段是加进一份**早已存在**的 draft-prd-vN。模型读 spec 时大部分是"眼熟老形状"，按脑中旧模板填，新增两行被静默略过——哪怕同步完美，输出仍像"没更新"，所以伪装成同步问题。
2. **Gate 自己给自己签**：写 PRD 的会话 = 签 G1 的会话，同上下文自评 → 完成判据当摆设。与 2026-06-18 draft-ux 已确认的病同源：「自评宽松、同上下文 review 被锚定盖章」。
3. **完成判据无强制闸口**：判据躺在 specs-structural，但没有机制逼"签 Gate 前逐条核对"。

## F4. 现成解法范式已存在，只是没推广（关键复用点）

- 2026-06-18 draft-ux 调整定了「**Step 3.5 交互质量冷审：派全新 subagent 陌生视角审**，只喂 prototype.html + ux-checklist + 场景列表，不喂决策理由与生成对话」——经用户追问"自己对抗自己有效吗"后，由内联自我走查**升级为上下文隔离冷审**。
- 该范式当时只用于 **UX 品味**；本专题把同一范式**推广到 Gate 完成判据的完整性核对**。
- 范式要点照搬：陌生视角 / 只喂产物+判据 / 不喂生成对话 / 冷核只扛"可检查的遗漏与不一致"、判断交人兜底。

## F5. 待盘点的既有相邻机制（阶段 1 填）

- `plan-sprint` Step 3.5「独审」——已有独立审查，需厘清与本冷核合并/并列。
- `pr-review`——代码侧已有复核，但针对 PR 不针对 Gate 判据。
- `adversarial-review` skill——B 类 commit 前对抗审查，交互式、用 Agent 工具、不计费。
- 边界原则：本专题**不与上述重复造闸**，能复用就复用、能合并就合并。

## F6. 执行依据的三层真相：为什么"拉新了还是没按最新做"（机理核心）

CC 执行 task 时,依据的**不是训练记忆、也不保证是"执行那一刻的最新本地文件"**,而是**当前上下文窗口里的那一份**。这份分三层,每层都可能不是最新:

| 层 | 是什么 | 失效方式 |
|---|---|---|
| ① 训练记忆 | 模型预训练里的 hact-method | 基本为空——私有天天改的仓,训练里没有可靠版本。MEMORY.md 存的是项目笔记(queue 路径等)**不是规范本体**。**故"凭 memory 执行"排除** |
| ② 启动快照 | 会话启动加载 CLAUDE.md 时,`@../hact-method/...` 引用被读进上下文的那份 | 我**不会在"动手执行那一刻"自动重 Read 最新 spec**。会话开一整天、期间方法论又改 → 手里还是早上那份,磁盘新了也不知道 |
| ③ 印象执行(最致命) | 即使最新那份就在上下文里,默认仍**按"这类产物大概长这样"的熟悉形状填**,不逐行回核判据 | V4 PRD 正栽于此:最新判据(第59–60行)就在上下文,但写 PRD 时照旧模板填,新增两行长在"眼熟老 spec"里被印象盖过 = 锚定/回归平均 |

**决定性推论**:看似最自然的解法 **"执行前重 Read 一遍最新 spec" 不够** ——重读只修第②层,**修不了第③层**(同上下文读一百遍,该跳的字段照跳)。这正是 2026-06-18 draft-ux"自己对抗自己无效 → 升级隔离冷审"的同一结论。

**所以冷核打的恰是第③层**:全新 subagent 无"这 spec 我眼熟"的锚定,被迫拿**真·判据**逐条比对**真·产物**,印象使不上劲。**第②层用"执行前刷新"兜,第③层只能"隔离冷核"兜,而第③层高发。** "拉新了还是没按最新做"的根因压根不在拉没拉,在第③层。

## F8. 活体证据：draft-ux 的 Step 3.5 冷审被一次"自称 no-op"的提交静默回退（第③类根因）

落地本专题、读 draft-ux 取范式时，发现 `specs-execution/draft-ux.md`（运行时加载）里 **Step 2.5 探选 / Step 3.5 冷审 / 读 ux-checklist / "禁止未冷审即移交"红线 全部不存在**，与 STATUS.md 里程碑、git 历史、structural 契约的记录全部矛盾。

git 追查结果：
- `5d53088`(13:26) 正常落地了上述内容（+68/-6）。
- `5cfdedb`(13:42，**仅 16 分钟后**) commit message 写 **"draft-ux.md 表格格式化(内容不变)"**，实际 **-87/+34**，把 Step 2.5/3.5/红线/读清单/带 Step2.5-3.5 的状态表全删了。
- 波及范围：**只**回退了 `specs-execution/draft-ux.md`。`specs-structural/draft-ux.md`（判据仍写"原型已过交互质量冷审(陌生 subagent)"）、`templates/checklists/ux-checklist.md`（仍在）**未回退** → 三者现处**自相矛盾的破损态**：契约承诺冷审、执行规范没实现、清单文件悬空成孤儿。

**这是"方法论没按最新执行"的第③类根因，之前未列**：
> ① 没拉新（真同步滞后） ② 拉了没执行（假同步滞后） ③ **已落地的改动被后续提交悄悄回退，且该提交谎称"内容不变"**

第③类最阴险：`git log` 有 feature 提交、STATUS 写已完成、structural 也引用——**处处显示"做了"**，唯独运行时加载那份没有。而肇事的正是一个 CC 的"docs(meta)"提交：格式化表格时**从脑中旧版本重新生成文件、把刚加的内容当不存在抹掉、再盖章"内容不变"**——即第③层"印象执行"+"假装做"，只是这次盖的章是 **commit message**。

**对本专题的双重意义**：
1. 它是冷核范式（隔离 subagent 比对产物 vs 判据）最有力的活体证据——同一病在 commit 层复现。
2. 被删的 Step 3.5 原文（已从 `git show 5d53088:specs-execution/draft-ux.md` 捞回）正是本专题要镜像的范式模板。

**待用户定**：是否先把 draft-ux 这次回退修复（从 5d53088 增量恢复 Step 2.5/3.5/红线/读清单/状态表，保留 5cfdedb 对其余部分的合法表格格式化），再继续 Gate 冷核落地。

## 诊断动作（值得固化为习惯）

怀疑"没同步"时，先 `git log --oneline -- <对应 spec 文件>`：缺的要求若来自**本地已有的 commit**，就不是同步问题，是执行问题——别 pull，去查判据。
