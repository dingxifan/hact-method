# 管理减法与 B 类轻量化

基线 `f1acd0c`，沿用 `codex/context-reduction`；仅方法论仓，不分发、不部署、不修改项目仓/个人仓/用户全局配置。

## 已确定的范围

- **暂缓** A 类主流程整体重构：保留 PRD→TRD→任务规划和 G1–G5 顺序，不取消整期 TRD/G3 前置。G5 仅减行政负担，仍保留必要收尾与人工确认。
- 管理减法：个人 notes/收割不再是立项和开发完成前置；学科只作可选知识分类，不充当真实授权；状态收敛到 status.yml；成本计时不阻断交付；反馈不以清空证明处理；按实际需要保留资产和决策索引。
- B 类调整（用户追加授权）：先调查实际代码，再用问题/预期/验证与明确边界推进局部修复/小优化。共享接口/类型的局部兼容变化允许显式 governed，但不是放宽业务、权限、迁移或不可逆操作；真实契约变更必须先有原始意图/确认依据，未知不能冒充安全。

## 实施顺序

| 批次 | 内容 | 必须保留的验证 | 状态 |
|---|---|---|---|
| 1 管理附加链 | 去掉强制 notes 建仓/分流，简化身份/学科、资产登记与归档 | 授权/负责人/风险裁决仍明确，原私人数据不动 | 已完成 |
| 2 状态与 G5/计时 | status 单一动态状态；sprint 为规划，任务包为契约；G5 去清空/措辞门；时间改可选 | 依赖/未合并/审查链/finding/真实 Git 仍拦截；Gate 签署与 hook 对应 | 已完成 |
| 3 B 类 | 先只读诊断、短包、实际契约影响分流 | none 夹带契约失败；governed 必需依据；迁移/越界仍失败；A 类前置不变 | 已完成 |
| 4 收尾 | 消费者核对、相关回归、成本与边界记录、提交 | 新旧状态冲突以真相源判定；不重写历史产物 | 已完成 |

记录只维护此文件；删除机制同时删除专属正文/脚本/测试义务。先把动态状态单源落好，旧项目的重复视图保留作历史，升级须逐仓核对状态与活跃任务，不能直接删项目文件。

## 验证与边界

- 14 组 scripts 回归全部退出 0；27 个 JavaScript 文件语法检查通过；check-paths 扫描 108 个运行时文件零绝对路径；git diff --check 通过。
- 新增 check-gate 回归实际运行 shell hook：status-only 的 G1/G2/G3 路由、G5 真实修订阻断、B merged 缺审计失败、未暂存版本不能给已暂存版本背书。G1/G2/G3 这部分用路由替身，真实检查器另有原有专属回归，不宣称真实项目验收。
- B 正反例：局部类型 governed 可进入独审；none 夹带类型、缺原始依据/写集/逐条 oracle、未知 schema、权威文档修订、status 签署夹带、源码隐藏 DDL 均失败。静态通过不证明兼容性，preflight/独审仍须核调用方和原始意图。
- 计时全部缺失仍按实际 Git 和审查链通过；虚假 tree/hash、首轮非 full、未闭合 finding 等原反例继续失败。schema 2 缺审查核心字段硬失败，不再误当历史放行。
- 新五列 sprint、无状态任务包仍通过 G3；旧包伪 merged 不覆盖 status 中未合并依赖。原 wave/worktree 整组恢复、共享资产冲突和 U/S 用户任务引用回归全绿。
- 删除仅为方法论中的 b-tasks/Gates 两份重复模板及个人 notes 两份建仓模板，可由 Git 恢复；现有项目/私人仓数据与权限未动。旧 notes 登记/游标在本仓冻结为历史，停止自动消费。
- 成本统计包含正文、脚本、测试、配置与本计划：净减少约 1,000 行；不以行数代替质量或真实节时。没有做真实项目长程开发试点，压缩后的保持率与实际耗时仍待样本。
- 未推送、未分发、未部署。存量项目升级须逐仓确认、核状态并一起更新 hook/checkers；不覆盖既有 hook、不改旧报告。A 类主流程重构保持暂缓。
