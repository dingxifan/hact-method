# GIT-API 改造：从"场景矩阵（safe middle）"转"穿透 + 边界"

> 设计稿 · 2026-07-12 · 改造既有机制 `generate-integration-tests` 的 API 侧（非新增机制，冻结相容）
> 承：`方法论待议.md` 2026-07-12「GIT 价值挪位」条 + empirical-harvest `generate-integration-tests` 改造候选。
> web 侧本轮**不动**（已转"人类可选驱动"，用户明确不改）。

## 一、病灶（两点实证 + 信息量论证）

上游（行为化 AC 链 + per-task 对抗独审跑真库全量+反例）已清"装配整体跑通吗"。现状 GIT-API（exec Step 2）**按接口逐条生成场景矩阵**（正常/鉴权/错误码/跨模块点）——测的是 safe middle，per-task e2e 已覆盖同样的东西。结果：harvest 2/118 + doc-extract v1 后端 0/31 全绿 0 命中。

核心：**不只低命中，是低信息量**——全绿的场景矩阵近乎无信息（测的地方本就不会错，全绿不能证接缝/边界成立）。上游变强没有消灭集成层价值，是把价值**挪位**：幸存 bug 只剩三缝——(a) 跨模块/管线接缝 (b) 真实外部边界 (c) 真浏览器/真数据（web，本轮不管）。现状 GIT 恰好绕开 (a)(b)。

## 二、形态（form 1：穿透为主 + 边界为闸）

穿透（内部缝）与边界（外部缝）**自动化属性相反**——穿透确定性可自动，边界必须真调不可自动。故切成两味不同性质的料，别让真调污染自动绿。

### ① 穿透（drive-through）· 替换场景矩阵

- **是什么**：少数条真端到端流，每条驱动真实体从入口走到终态，全程走**真实 API + 真队列/转换机制**，**禁 fixture 抄近路**造中间态；断言每步转换真发生 + 终态到达 + 终态产物正确。
- **源**：从 PRD AC **主流程 + 各"不同结局"分支**取（不按接口枚举）。
- **数量 = 原则，非硬数字**：**每个"不同终态/分支决策"一条，对这些穷举、之外零条**（防退回场景矩阵的再膨胀护栏）。随输入种类多加 = 违规。单管线应用通常 ~5-6 条，多管线更多——**随真实终态数伸缩，不随输入种类**。异常小分支降 backlog。
- **为什么抓 safe middle 抓不到的**：per-task e2e 各自造起点 fixture、只测半边；穿透不许抄近路、必踩真实 enabled 边/真队列/真跨模块交接 → "边 enabled=false / 状态词汇不符 / 队列没接"（de-v1-004 类）当场断在推不动处。
- **失败语义（改掉现状"默认自动改"）**：默认**升级裁决、不自动 patch**。**⚖️ CC 自动判两路、可推翻**（"契约问题还是代码 bug"多能从"边在不在库里"机械判）：
  - **意图≠as-built** → `revise-doc(target=trd)` 或地基裁决，不当普通 code bug 反复改；
  - **纯实现 bug** → `source=integration` develop 任务（同现状）；
  - 极窄快速通道：仅**测试脚本自身**写错（断言值/typo、无业务改动、原因显然）当场修。
- **附带红利**：穿透是"as-built 对账"待议发现的**机械兜底**——就算 draft-tech-design 没做对账，穿透在集成阶段把 TRD↔as-built 脱节撞出来。两条待议在此合流。

### ② 边界闸（boundary smoke）· 闸控 opt-in 子步

- **触发（桩点即边界）**：不新增字段。per-task 测试在哪打了桩（引擎白名单/外部 SDK/外部 HTTP，"绝不真调付费 API"），哪就是零真调覆盖的边界。**CC ⚖️ 自动扫本期 diff/测试的桩点 → 列出本期新增/改动的真实边界**，提议冒烟。
- **真调这一步 = 🚫**（非 ⚖️）：花钱 + 打真外部 = "对外、难撤销、先确认"类，决策#28 收敛 🚫 亦保留此类。**探测是 ⚖️、真打是 🚫（人点头才打）**。
- **做什么**：每条边界用**人工临时提供的小真样本**（不入库——PII）打**一次真调**，断言**接线对真实世界成立**（鉴权方式/真响应形状解析/真行为 204·超时·token 格式），**不测业务正确性**。抓飞书 OIDC 方式错 / HTTP 204 误判 / OSS 超时那类。
- **跑不了非静默降级**：无凭据/无环境 → 标"边界冒烟未跑、边界 X 真调未验"→ 移交 manual-test / deploy-smoke，不假装绿（沿用 doc-extract v1 web 降级姿势）。
- **失败语义**：真调失败 = 接线错 → 升级 `source=integration` 带真证据修，不自动 patch。
- **位置**：留 GIT 内做闸控子步，**明确在自动绿之外**——失败产 finding、不卡自动套件的绿。

## 四、冻结 / measure-first

改造既有机制（harvest 已挂改造候选），**非新增机制**，冻结相容。GIT-API 已够 2 点实证支撑"现状低价值"方向。**但新形态本身未跑过 = 假设**（穿透信息量更高）——land 后**下一次 GIT 运行即改造自身的第一手验证**（穿透是否比矩阵多抓、边界闸是否真拦外部接线）。
