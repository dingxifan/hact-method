## 一、痛点起点

不是某功能不顺，而是对整套方法论的根因质疑——"无休止加规范来规范 AI，能不能持续？"。独立 subagent 对抗审查 + 人工综合，挖出两个**全局结构性错误**：

- **错误 A · 质量模型方向错**：规范/Gate/冷核都在验"指令有没有被遵循"，不是"产物到底对不对"。真正验输出的只有流水线最末端（集成测试+人工验收）——在最便宜处验最便宜的事，在最贵处发现最贵的问题。
- **错误 B · AI 不可靠被当成"规范写作问题"**：AI 是概率系统，规则塞进 spec = 塞进 context = 越长越失真 → 正反馈退化回路。

最尖锐证据：2026-06-18（本轮前一天）刚加的 Gate 冷核协议本身就是病灶——往"AI 盖章"问题上再叠一个 AI。
底层另有 8 条结构问题，#1（develop 5 合 1）、#3（Gate 无机械闸）、#4（非技术管理者签不动技术 Gate）最重。

## 二、初始解决方案（design.md）

方向：把**正确性维度**从"散文规则 + AI 肉眼核"迁成"确定性检查（test + linter + 一致性检查器）"，**每迁一条删一条散文**。
防自我背叛判据：**成功 = spec 净收缩**，不是"新增验证能力"。
三定调：① 火力集中**不可视区** ② 核心抓手 **A：AC→可运行测试** ③ Gate = 检查器全绿 + 少量语义人签。
拆 4 个串行子计划（§11）：1 地基 → 2 不可视区 → 3 Gate 重定义 → 4 可视区收口。

## 四、偏差分析（5 处，按重要性）

1. **成功判据本身没真正兑现（最大）**：§2 钉死"spec 净收缩"，实测全局散文净只删 **14 行**，sub7 还 **+102 行**。真删的是"AI/人眼**步骤**"（冷核 ×N、Step5.5、checklist 砍半），不是散文**行数**。文档自评"及格但不漂亮，地基铺得比散文删得多"。严格按 §2 尺量：**判据部分落空**。
2. **最深的杠杆全程没碰**：findings §二 + design §2.5 都点名 **loop 第二层**（per-module/API 小循环 + TRD shared-type-first）才是真正让 generator 变瘦的线。这轮做的全是**第一层**（换验证器类型）。第二层从头 park 到尾。**最能兑现"减规则、可持续"初衷的线，一次没动。**
3. **sub7 性质偏移 + 一度被误框**：develop 拆分是 findings #1，但不在 §11 的 4 子计划。做了，却以"+102 行、非 §2 净收缩"落地；CC 一度在 AskUserQuestion 误框成"满足 §2"被纠正。落地诚实，但暴露"想把 reorg 包装成净收缩胜利"的滑动。
4. **hook / CI 凭证降级**：§11.3 原设计的 B3 hook 守签字 + Gate 凭证改 CI，前者多次定"不做"，后者用更轻的"检查器绿+人签"替代。机械闸门仍是软的，findings #3"Gate 无机械闸"**只缓解、未根除**。
5. **子计划 3 裂成三个（合理偏差）**：建 G3 检查器前实测任务包撞上"跨迭代格式漂移"硬障 → 被迫先做规范化（sub3c）。发现驱动的合理膨胀，反证"先实测产物再写检查器"纪律有效。

## 五、落地盘点

**真落地（✅）**：质量模型方向转向（贯穿 7 子计划无背离）/ 地基结构化模板+check-docs.js / 不可视区 AC→test+删 Step5.5 / **Gate 五关全建检查器 + §7 冷核协议整段拔净**（最实净收缩）/ 可视区 checklist 三段式 / **AC 链路三段全机械对账** / develop 拆 core+3 薄壳兑现决策 #14。

**Parked（⏸️）**：**loop 第二层**（最该做却最没做）/ PRD AC id 跨迭代永久化。

**未做 / 降级（❌）**：B3 hook、Gate 凭证改 CI（降级）/ findings #6 B/A 类边界静默渗透（未启）/ findings #7 多工作区同步漂移（未启）/ PRD 改 generate→validate（设计上判定不做，正确）。

**落地状态硬事实**：7 子计划全在**本地 master**，领先 origin 十几 commit，**从未 push**。落地进了仓库，没出本机。

## 六、总评

> **方向落地了，判据没完全落地，最深的洞没挖。**

诊断质量极高（A/B 全局错误 + 活体抓拍冷核协议自打脸），方向干净，执行纪律好（每子计划过对抗审查、有诚实净收缩账、不 spin）。**但成功货币（净收缩）只兑现"删步骤"一半，"删散文行"一半被地基代码+接线吃掉**；真正能让规范瘦下来的 loop 第二层从头 park 到尾。findings #6/#7 两个结构漏洞整轮没碰——它们不在"正确性可测试化"射程内，是另一条独立战线。

**病诊对了、药对路，但抓的是温和那味（人眼/AI 验证换机械验证）；最猛那味（拆小生成单元、让 generator 真正变瘦 = loop 第二层）还在药柜里。** → 下一轮重启 loop 第二层。
