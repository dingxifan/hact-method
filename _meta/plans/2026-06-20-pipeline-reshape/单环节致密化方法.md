# 单环节致密化方法 — 以 draft-prd-vN（PRD 阶段）为完整样本

> **来源**：2026-06-20 单环节 loop 试点。先把 PRD 阶段当样本做"全套"（四件机制 + 致密语言全部到位），从中抽出可复制到其余 spec 的配方。
> **解决的病**（findings §七）：规则进 spec = 进 context = 越长越失真，"再写一条禁止 X"是退化回路。能真正改变 CC 行为的只有三种机制——**更小 context / 确定性验证器 / 结构性强制**——不是更多散文。

---

## 一、四件机制 + 一把语言刀（PRD 样本已全部落地）

| # | 机制 | 治什么 | PRD 样本落点 | 删掉的散文 |
|---|------|--------|-------------|-----------|
| 1 | **template 接填写说明** | 格式/字段规则散在 spec 正文、每份重抄 | `templates/prd.md`（字段格式 + AC id 规则 + 例子写法全进 HTML 注释；linter 按模板解析） | spec 正文不再抄格式（"本文只讲过程与判断，不重抄格式"） |
| 2 | **linter = 判官** | 结构完备/交叉一致靠人或 subagent 肉眼扫 | `scripts/check-docs.js`（Step 7.4 自检） | "派 subagent 冷核"协议整段（结构性审查已删） |
| 3 | **门卫 = forcing function** | "记得跑 linter、退出码 0 才签"本身还是条会失真的散文 | `scripts/pre-commit-hook.sh`（init-project Step 4.1 装进 `.git/hooks/`） | "不得手改报告、不得跳过""签字前置：退出码 0"——门卫使"跳过判官偷签"机制上做不到 |
| 4 | **末端独立 agent 审内容** | 格式之外的**内容有效性**（一致性/AC 可验性/覆盖）同上下文自评会盖章 | Step 7.5 派全新陌生视角 subagent，只喂定稿、不喂生成对话，**输出问题清单非 pass 盖章**；审查维度写成**派发 brief 逐条原样喂 subagent** | — （这是 ADD，但 ADD 的是"验内容"不是"堆规则"） |
| ✚ | **致密语言（最大那刀）** | spec 大量篇幅是给人读的**教学体**冗余，真读者是 CC（要指令体非教案） | 正文逐句换语气：教学→指令 | draft-prd-vN 311→165 行，最大单刀 ~70 行就是"换语气"，**不搬知识、不抽共享段** |

## 二、职责分工矩阵（配方的核心——四象限各有归属，正文只剩第四象限）

```
格式对不对          → linter（判官）+ 门卫（强制跑）   ← 机制，不进正文
怎么填/字段规则     → template（HTML 注释带说明 + 示例） ← 模板，不进正文
内容有效不有效      → 末端独立 agent（陌生视角问题清单） ← 机制，不进正文
─────────────────────────────────────────────────────
过程与判断          → spec 正文（且换指令体）           ← 只剩这块，自然致密
```

**关键认识**：spec 之所以胖，不是知识多，是把"格式/填写说明/验证仪式"一遍遍写进正文。把前三象限各自交给 template/linter+门卫/末端 agent 后，正文只剩"过程与判断"，再换指令体 → 自然致密。

---

## 三、为什么门卫是缺的那块拼图（判官 + 门卫）

- **linter（判官）只能新增能力、删不掉散文**——因为"记得跑 check-docs.js、退出码 0 才签字"**本身还是一条散文规则**。
- **门卫**自动跑判官、红了就拦 commit，那句散文才能**整段删**——强制它的不再是文字，是闸门。
- 这是 findings §七-3「forcing function」那第三种、**本方向唯一没碰过**的机制。地基（结构化模板）✓ + 判官（linter）✓ 早就位，缺的就是门卫。

**门卫实现要点**（`pre-commit-hook.sh`，已测三场景）：
- 按 staged 文件路由：`prd.md`/`trd.md`→check-docs、`sprint.md`/`queue/`→check-sprint、`gates.md` 新增 G4/G5→check-gate。
- **暗礁兜底**：脚本缺失 / node 缺失 → **no-op 放行**（存量仓 hact-app v1–v4 不被拦死）。
- **护栏非密码锁**：`--no-verify` 可绕、`.git/hooks` 不随 clone（队友须重装一行）。是**合作者的强制出路、非安全边界**——与 Goodhart 风险同源，接受并明示。

## 四、诚实账（每件机制的货币不同，别混框成"净收缩"）

| 机制 | 货币 | 是不是净收缩 |
|------|------|-------------|
| 致密语言 | **真净收缩** + 零 sub7 陷阱（只把同义写短，不搬知识不抽共享段） | ✅ 最大那刀 ~70 行 |
| template 接填写 | 单一来源防漂移（格式规则一处改） | 搬，正文减但模板增（净微缩） |
| linter 判官 | 确定性（跑一万次一致、不受 context 失真） | 删肉眼扫步骤（小净缩）；ADD 是 code 不进 context |
| 门卫 | **forcing function**（对的事成为唯一出路） | 删强制散文 ~3–5 行/份；ADD 是脚本不进 context |
| 末端 agent 审内容 | 陌生视角逮跨功能缺口 | ADD（验内容非堆规则，不背叛净收缩判据） |

> **不得据某一件宣称总净收缩**：致密语言是真减肥主力；template/门卫是"搬 + forcing"，货币是防漂移/强制力。四件凑齐才是"完整致密样本"，单看行数会误判。

## 五、套到下一份 spec 的步骤（可复制）

1. **拆四象限**：把该 spec 的内容逐段归类——格式规则 / 填写说明 / 验证仪式 / 过程判断。
2. **格式规则 → template**：搬进对应模板的 HTML 注释（若无模板先建，沿 `templates/prd.md` 同款）。
3. **验证 → 判官 + 门卫**：结构判据有 check-\*.js 覆盖吗？有则正文删"记得跑+退0才签"散文（门卫已接管）；缺则记为待建检查器（先留兜底散文）。
4. **内容有效性 → 末端 agent**：是否需要陌生视角审？需要则加一个"只喂定稿、输出问题清单"的 subagent 步（沿 Step 7.5 同模型）。**审查维度必须写成"派发 brief、逐条原样喂 subagent"**——subagent 是全新上下文，只知道 prompt 里有的东西；写成"给 CC 读的审查范围"则全靠 CC 临场自觉塞进去，漏了就退化成泛扫 + 盖章。判官/门卫的指令固化在 code，末端 agent 的指令必须固化进 brief。
5. **过程判断 → 换指令体**：剩下的正文逐句教学体→指令体（最大 ROI 一刀，零 sub7 风险）。
6. **诚实记账**：每删一处先答"删的是哪条散文 / 哪个验证步"；删不动记成"结构改进"，不误框净收缩（守 design §五 sub7 纪律）。

## 六、边界与残量

- **门卫只覆盖"有检查器的结构判据"**：check-docs（G1/G2）/ check-sprint（G3）/ check-gate（G4/G5）。无检查器的 spec（develop 家族等）门卫无可跑、退 no-op。
- **致密语言有上限**：用户验收 PRD 时判"直觉还有 10–15% 空间但已 <200 行，先这样"——换语气到一定密度后边际收益递减、误读风险微增。
