原点 · 三条北极星（质检设计的判据）

1质审前移在最便宜、最早处验证质量。坏 AC 应在需求阶段暴露，而非拖到联调 / 验收。
2质量控制 ≠ 规范控制验"产物是否真的正确"，靠确定性检查（test / linter / 一致性检查器）+ 精准输入，不靠再加散文规范。
3优化上下文 + 精准输入更小上下文、确定性验证器、喂 subagent 权威原文（非自评 / 转述）——能真正改变 AI 行为的三个杠杆。

全部 🔧 确定性检查器（linter / test） 🚪 门卫（pre-commit hook） 🔍 独立对抗审查（subagent） 🧑 人工门（签字 / 品味） 🧵 测试脊柱（贯穿）
提示：「确定性检查器」由 check-docs.js / check-sprint.js / check-gate.js + build·type·lint·test 承担；「门卫」红则拦 commit，让"跑判官"成为提交唯一出路；「独立审查」全新隔离上下文、自读权威原文、拒收自评、存疑即阻断。
🧵 测试脊柱：一条不可视区 AC 的行为例子，无损穿过四个环节，最终物化成可运行测试——把"坏 AC"逼到最便宜处暴露。
PRD 幕1：写 Given/When/Then 行为例子→ TRD 幕2：精化为技术精确规格（状态码/错误码）→ 任务包：写进 acceptance-criteria + 回链 tag→ develop：1:1 物化成 runnable 测试并跑绿

主链路流程（点击任一环节查看详情）

develop 的三层质量防线（merge-on-push 后无独立 pr-review）

① 确定性绿（硬底）build / type-check / lint / test 全绿。执行 subagent 增量自绿 + 末端全量检测，不受上下文失真影响。
② 独立对抗审查（语义 top-up）全新隔离 subagent 自读权威原文（任务包 / diff / standards / 测试），对抗式找问题、拒收自评、存疑即阻断、3 轮升级。
③ 人工门（仅 2 处）前端设计到位（开跑前）+ 安全敏感改动（权限/认证/数据隔离）合并前 architecture 裁决。其余全自动合并到 master。
