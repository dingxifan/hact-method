## Retaining `integration-verify`

Repository evidence supports retaining `integration-verify`:

- it is already Core Task 9 in `tasks/README.md`;
- `templates/boot-protocol.md` routes the old name to it;
- `tasks/manual-test.md` already depends on it;
- its present scope already includes cross-task semantic composition checks and real runtime paths.

There is no repository fact that requires a new `system-review`, `final-review`, or `system-verification` Core Task. The real work is semantic expansion, artifact alignment, and compatibility cleanup.
