# Phase 1 — Implementation Risks

| Risk | Repository evidence | Failure mode | Required control |
|---|---|---|---|
| Historical schema compatibility | Existing package reports and status entries predate current fields; repository policy preserves them. | New checker rejects accepted historical truth or encourages fake backfill. | Apply new schema prospectively by adopted method/schema/event presence; never infer absent evidence. |
| Duplicate truth | `status.yml`, detailed package rounds, runtime result tables, and archives already divide machine index from detailed evidence. | A new system ledger duplicates finding state in status and report files, then drifts. | Keep detailed system truth in immutable/additive Git artifacts; status stores only pointers/obligation summary needed for routing. |
| Core Task identity churn | Active vNext uses `integration-verify`, while legacy docs still use `generate-integration-tests`. | A new task is added or old alias becomes a competing canonical identity. | Preserve `integration-verify`; make legacy name input-only alias and align distributed surfaces. |
| Review state duplication | Task state is `可取|taken-by|done|merged`; target finding state is separate. | `repairing/testing/reviewing` become new durable task/finding states without need. | Keep transient activity in progress/recovery artifacts; persist only open/closed/escalated system finding truth. |
| Checker/runtime semantic drift | Review rules live across Task, Protocol, Runtime, templates, and checkers. | Checker enforces a different route/invalidation rule than the normative contract. | Freeze normative semantics first; make checker fixtures derive from explicit invariants and negative cases. |
| Reviewer isolation assumptions | Codex runtime can create Fresh Isolated Context, but capability may vary. | Same implementation context self-approves a local/system finding. | Preserve protocol capability-gap behavior; closure must record isolation mode/evidence. |
| Report parsing brittleness | Current checkers intentionally parse controlled Markdown/YAML subsets. | Flexible prose or YAML shape changes silently evade or falsely fail checks. | Define a narrow frontmatter schema, reject ambiguous shapes, and test negative mutations. |
| Completion deadlock | Target completion aggregates semantic review, runtime, findings, escalation, and revalidation. | A stale pointer or orphaned obligation makes System Verification permanently unreachable. | Checker must diagnose the exact unresolved obligation; recovery contract must identify the next action and authoritative artifact. |
| Accidental Full Review escalation | Current package schema has `escalate_to_full`; target adds system invalidation. | File count or any cross-package change triggers costly full review. | Require explicit invalidated conclusions and reason; test that large local diffs can remain targeted and small contract changes can invalidate. |
| Under-review of sensitive packages | Current `risk` can be self-declared and standard review remains full today. | Lightweight policy lands before actual-diff escalation, weakening security/billing/destructive boundaries. | Land classification/effective-mode separation and escalation checks together; retain sensitive hint and Human Authority regressions. |
| Package/System review conflation | Existing full/targeted vocabulary is package-scoped. | A package full review is treated as the one System Full Review, or a system targeted event claims whole-system assurance. | Use distinct schema/path/identity and require declared system scope/predecessor. |
| Mutable judgement | Runtime result currently updates the same retest row. | Semantic judgement is overwritten after repair, erasing why it was blocked. | Keep runtime result separate; system review events immutable; closure evidence additive. |
| Finding disappearance | Current package checker carries target ids, but no system checker exists. | A new system report omits an earlier blocker and appears green. | Dedicated checker must reconcile predecessor findings and closure/escalation lineage. |
| False completion from green runtime tests | Current integration completion is runtime/composition centric. | `integration-verify` completes without semantic review. | Make both lanes explicit and mechanically required for new System Verification cycles. |
| False completion from semantic pass | Target semantic reviewer may request runtime evidence. | Review passes while runtime scope is missing/failed. | Separate result/evidence axes and validate required runtime scopes. |
| G4 bypass | `check-gate.js` currently checks manual-test repair state and acceptance report, not system review. | G4 is signed with open system blocker or pending rereview. | Add G4 consumption only after the dedicated system checker is stable. |
| Legacy alias drift | Skeleton/guide/spec execution still name the old task. | New projects or operators enter the wrong contract surface. | Align current distributed docs in Phase 2; preserve old project files as historical evidence. |
| Overloading `check-sprint.js` | It already owns a large package/planning audit. | System rules make it brittle and cross-couple unrelated staged changes. | Prefer a narrow `check-system-review.js`; call it from hook/gate. |
| Persistence-system invention | Target needs closure evidence but repository already has review rounds, status pointers, result evidence, and archives. | A database-like review ledger/state machine is added. | Reuse directory events + status pointer; require evidence that existing patterns cannot satisfy a field before adding structure. |
| Frozen experiment contamination | A/B artifacts are empirical baseline. | Implementation edits or reruns them and changes comparison truth. | Path-diff guard and explicit no-rerun rule in every phase verification. |

## Highest-risk sequencing constraint

Do not enable standard lightweight Package Review before the System Verification semantic lane and completion contract are executable. Otherwise assurance responsibility is removed from packages before it has a valid destination.
