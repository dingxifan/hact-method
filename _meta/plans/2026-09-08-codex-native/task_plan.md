## 目的与约束

让 Codex 在已授权范围内连续完成开发，同时保住用户任务、契约、独立审查与有效验证。删除 CC 兼容和重复编排；既有 Git 状态、任务包、进度与报告是恢复依据。压缩次数不作为质量或暂停阈值。保持安全/业务裁决、真实审查、固定 diff、共享写集约束；不因减法抹除历史报告或在制品。

## 实施判据

- 不另建规则库、任务状态协议或重复报告；新增内容必须替代既有动作。正文/脚本/测试/记录一起算账。
- 执行单元可直接使用当前上下文或另开不继承历史的子代理；只有独立且有收益时委派。独审输入来自任务/原文/固定快照，不继承实现叙事。
- 用户授权的任务集可跨压缩继续；内部按可验证单元推进。既有单元切换/恢复无需重新授权，业务取舍或越出原范围仍停。
- 用户任务指用户要办成的事，允许跨功能/页面；不能等同开发包。验收实际任务结果与可恢复性，AC 映射用于查漏。
- 测试重点覆盖行为与迁移风险，不为文档句子逐字编造测试。真实多次压缩的模型保持率和实际节时需要后续项目样本，不用夹具通过代替。

## 执行记录

- 开始：当前工作树干净；相关历史、运行时接口、用户任务 UX 和长程恢复要求已核对。
- 批次 1：单入口/角色继承/15 个状态路由检查通过。移除运行时中立检查和四场景比较，保留状态路由为单 Codex 测试。未测试外部模型账号或远端能力；本批不改项目仓。
- 批次 2：主线实现与可选委派、冷审查、授权集跨批次推进及压缩恢复已接线。去掉固定 compact、文件数派发和逐类别自检报告。真实 Git 新进程连续恢复三次、未审修改拒绝、报告链与 wave 分拆通过；没有模拟模型内部压缩，也没有宣称测得检出率或节时。
- 批次 3：UX 改为 U-id 用户任务/S-id 场景，先写目标/起点/完成/动线，再生成页面；映射改为 AC→U/S→锚点/页面，允许多功能共页。检查器从 PRD 定义核遗漏，不再要求功能与页面同名。前端开发须引用真实 U/S；TRD 与真实集成沿同一用户任务承接，撤销前端 15 条硬上限。
