## §3 摩擦与真实偏离（成本面）

**§3.1 wms 未采纳 standards 归位（#17，2026-06-20）——真实合规缺口**
wms 把 standards 留在 `iterations/vN/standards-*.md`，**v1–v4 共 4 套副本**，正是 #17 要消灭的"副本链 + 真相源含糊"。loxson 已归位到项目根（CR10/CR22 记 revise-doc 迁移）。关键：wms v4（07-02，晚于归位 12 天）**仍用旧布局**。
→ **新经验：方法论中途改规范，在飞的存量项目不会自动迁移。** 规范变更需要显式的存量项目迁移动作，否则新旧布局长期并存、真相源含糊。这条应进方法论演进策略（值得考虑：变更规范时同步产出"存量迁移 checklist"或 revise-doc 触发条件）。

**§3.2 真实外部边界是 mock 驱动开发的结构性盲区——加投方向第二组独立实证**
loxson `salary-b-001` 接真实 OA 时一次暴露 **8 个 mock + 集成测试全绿却漏掉的问题**（V11-6~13）：getuserhists 30s 超时 / getusers **47% 数据因 NOT NULL 约束静默丢失** / **整合层完全无 LABOR 分支**（A 类规模数据模型缺口）/ 顶级部门 parent_id 丢失。
→ 精准坐实记忆中「加投方向 = 真实外部边界冒烟 + 生产静默失败告警」。这是继第一组（≥3 bug 归同一缺失）之后的**第二组独立实证**——当前 mock 驱动 develop + 集成测试对真实外部系统是盲区，且失败以"静默丢数据"形态出现（呼应"静默失败告警"投向）。

**§3.3 多人协作的决策漂移——decisions.md 承住了**
loxson decisions 多次 `撤销`/`推翻`/`取代`（D-v1.2-01 撤销、D-v3-03 推翻 D-v2-01/04、D-v2-05 取代原"不可改字段"方案）。决策记录机制真在捕捉在飞方向反转，未让翻案变隐性知识——多人场景价值点。

**§3.4 status.yml 维护密度在多人组下降**
wms（单人）67 锚点 vs loxson（多人）13 锚点。多人下机器侧状态契约维护纪律松，看板取数源完整性在团队场景打折——与第五阶段团队引入直接相关的风险信号。

## §4 结论与对冻结决策的意义

1. **主干稳**：两个独立真实项目、单人与多人（+Codex）两种编制，都跑通完整 PRD→TRD→sprint→develop→部署闭环；58 Gate / 57 审查发现 / 16 B 类返工 / 8 manual-test 拦截 / 一次真实 Codex 全流程。
2. **成本面清晰**：多人摩擦（100 merge / 2 revert / status 维护松）、规范中途变更不自动迁移、真实外部边界 mock 盲区（8 个 OA 问题）。
3. **对冻结决策（#25–#29）的净影响**：
   - **加强**了"加投方向 = 真实外部边界"的信心（第二组独立实证）；
   - **未推进** #25 V0 验证（两项目零覆盖，同第一组）；
   - #29 B 类兜底仍**数据缺口**（无真实触发）。
   → **这两项目是"主线机制"的强验证，但不是冻结那批新机制的解冻依据。** 解冻仍需等一个从 `init-project → V0 → V1` 起步的新项目。
4. **待议新增候选**：
   - 「规范中途变更 → 存量项目迁移动作」缺失（§3.1）；
   - 「多人场景 status.yml 维护纪律」松（§3.4），第五阶段团队引入前需正视。
