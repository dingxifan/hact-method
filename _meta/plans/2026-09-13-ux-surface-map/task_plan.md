# 用户动线到界面位置的中间层补格

## 来源与判断

file-extract 的真实设计对话暴露：虽然现行 `draft-ux` 已要求“先用户任务与完整动线，再页面与原型”，但没有强制记录页面、弹层、抽屉的归属、完成落点和返回位置。模型仍可能先拼页面，再从原型倒推动线。

本次判为既有用户任务 UX 机制的补格，不新增 task type、Gate 或产物文件。继续使用 `ux-flows.md`，在场景列表与流程图之间增加动线—界面地图；不把 file-extract 的套、文件、Workbook 等产品名写成通用要求。

## 纳入范围

- 明确主任务与辅助分支、页面与局部界面、对象归属、打开来源、完成落点和返回位置。
- 共用组件可复用，但新建/补充等不同模式各自保留起点、作用对象和返回上下文。
- 区分“任务完成后的落点”和“下一步可选对象”，未经确认不自动打开任一子对象。
- 对象创建时点、全失败/部分成功、重试保留、自动选择等可观察业务规则若未在 PRD AC 中规定，先回 `revise-doc(target=prd)`，不让 UX 偷加契约。
- 关键业务或信息架构取舍关闭前暂停原型；普通界面归属由执行者自主完成。

## 不纳入范围

- 不修改 file-extract 项目、现有原型或其已签 PRD。
- 不要求每个功能单独建页，不新增独立问题页或固定 Excel/PDF 页面模型。
- 不推送、不分发项目仓，不改 hook。
