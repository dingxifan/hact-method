# 行为规格管线设计 · 2026-06-26

## 背景

来自 mail-ai backlog 的活体证据：`排序持久化规则`、`搜索展开后路由跳转行为`（mail-rd-002 修订）、`AI摘要折叠`、`待办删除按钮触发方式`（模块24 视觉打磨）——这些决策都没在 PRD 或 draft-ux 阶段被显式逼出，最终散落进 backlog 或修订记录。

## 问题诊断：三类行为决策

| 类别 | 描述 | 典型例子 | 现状 |
|------|------|---------|------|
| **第一类** | 行业惯例已解决，无歧义 | 输入框失焦校验、Toast 位置、加载转圈 | 开发者套惯例，不需要显式决策 |
| **第二类** | 歧义来自产品语义，不来自交互设计 | 搜索字段范围、默认排序字段、软删/硬删、状态持久化范围 | **PRD 应覆盖但未覆盖**——AC 体系偏向用户主动动作，隐含的初始状态/数据策略不会自然浮出 |
| **第三类** | 歧义属于交互设计层，PRD 天然不覆盖 | 危险操作摩擦力、批量选中触发、表单未保存离开、空态 CTA 形态 | **draft-ux 应覆盖但未覆盖**——内部消化阶段显式跳过"组件细节" |

> **注：第二三类存在耦合**——软删/硬删（第二类）直接决定危险操作摩擦力（第三类）。严格的"两类分别由两阶段各自负责"模型在耦合处会产生盲区，见管线分工说明。

## 管线分工

```
PRD          → 主责第二类（语义默认值），能在需求阶段答清的尽量写成 AC
draft-ux     → 兜底扫描（第三类交互层歧义 + 第二类在 PRD 遗漏或依赖原型才能答的）
第一类        → 开发者自判，无需规格
```

**分工不是严格隔断**：PRD 尽量追，draft-ux 兜漏网。任何在 PRD 阶段因"需要看到原型才能判断"而未能回答的第二类决策，由 draft-ux item 5 接住。

## 具体改动

### A · PRD `draft-prd-vN` Step 4 逐功能展开

在逐功能写 AC 时，CC 识别功能类型，主动补问并写成显式 AC：

| 识别到的功能类型 | 必须有 AC 的隐含维度 |
|-----------------|---------------------|
| 含数据列表 | 默认排序字段+方向；空态行为（纯提示 / 有引导 CTA） |
| 含搜索 | 搜索字段范围（哪些字段被检索） |
| 含不可逆操作（删除/清空） | 数据是否可恢复（软删保留 / 硬删彻底清除） |
| 含跨会话持久化状态 | 持久化范围（session 内 / 账号级跨设备） |

这些维度用 Given/When/Then 例子写成普通 AC，与其他 AC 同等对待。若用户在 PRD 阶段无法回答（需要看原型才能判断），记为开放问题，标注"留 draft-ux 确认"，不强行关闭。

### B · draft-ux Step 2 内部消化：新增 item 5

画面构思（item 4）完成后，新增：

```
| 5 | 行为待决扫描 | 逐画面扫描，列内部清单（不外露）。扫描项：
                   · 危险操作摩擦力（直接执行 / 确认弹窗 / 手动输入确认词）
                   · 批量操作选中触发（勾选框常驻 / hover 出现 / 长按触发）
                   · 表单未保存离开（直接走 / 弹警告 / 自动存草稿）
                   · 空态 CTA 形态（纯文案 / 有引导按钮+指向何处）
                   · 权限受限时的 UI（隐藏按钮 / 禁用+tooltip / 操作后报错）
                   · 操作成功后的页面行为（停留当前页 / 跳回列表 / 刷新）
                   · 数据加载失败的处理（重试按钮 / 静默降级 / 整页错误态）
                   · 列表行点击行为（跳页 / 开侧抽屉 / 展开行内折叠）
                   耦合兜底：若某条摩擦力/行为决策依赖 PRD 中的数据策略
                   （如软删/硬删）但 PRD 未明确，标为待确认，Step 3 追问补齐 |
```

### C · draft-ux Step 2 出口 X：扩展触发条件

**现在**：`识别到关键决策点（多种合理走法 + 影响下游多画面）`

**改为**：满足任一：
- ① 结构性关键决策点（多种合理走法 + 影响下游多画面）
- ② 行为待决清单非空（存在交互层歧义或 PRD 遗漏的第二类待确认项）

### D · draft-ux Step 3 关键决策对答：双轨机制

**结构类决策**（承载方式/组织粒度/多步流程等）
→ 默认出 mini HTML——不点不出感觉，文字描述替代不了

**行为类决策**（来自 item 5 行为待决清单）
→ 默认文字问答，一问一答逐条过
→ CC 判断：能用一句话说清楚的用文字；无法用文字描述效果的（如空态布局、弹窗文案布局）主动出 mini HTML，不等用户请求

| 决策类型 | 默认方式 | 升级条件 |
|---------|---------|---------|
| 结构类 | mini HTML | — |
| 行为类 | 文字问答 | CC 判断该决策视觉依赖（效果无法用文字说清） |

Step 3 典型决策示例表补充行为类：

| [行为] 危险操作确认 | 直接执行 / 二次确认弹窗 / 手动输入确认词 |
| [行为] 批量选中触发 | 勾选框常驻 / hover 出现 / 长按触发 |
| [行为] 表单未保存离开 | 直接走 / 弹警告 / 自动存草稿 |
| [行为] 空态 CTA | 纯文案 / 有引导按钮（指向何处） |
| [行为] 权限受限 UI | 隐藏按钮 / 禁用+tooltip / 操作后报错 |
| [行为] 操作成功后行为 | 停留当前页 / 跳回列表 / 刷新 |
| [行为] 加载失败处理 | 重试按钮 / 静默降级 / 整页错误态 |
| [行为] 列表行点击 | 跳页 / 开侧抽屉 / 展开行内折叠 |

## 决策传导链

```
PRD Step 4
  ├─ 识别功能类型
  ├─ 补问语义默认值（搜索范围/默认排序/软硬删/持久化范围）
  ├─ 写成显式 AC（Given/When/Then）
  └─ 无法在 PRD 阶段答清的 → 标"留 draft-ux 确认"，不强行关闭
        ↓
draft-ux Step 1.1 业务沟通
  └─ PRD AC 已覆盖的语义默认值不再重问；
     PRD 标"留 draft-ux 确认"的项在此阶段业务沟通中补问
        ↓
draft-ux Step 2 内部消化
  ├─ item 1-4：场景/AC映射/流程/画面构思（不变）
  └─ item 5：行为待决扫描（第三类交互层歧义 + 第二类遗漏兜底）
             耦合兜底：第三类缺第二类锚点 → 追问补齐
        ↓
draft-ux Step 3 关键决策对答（触发条件扩展）
  ├─ 结构类 → mini HTML
  └─ 行为类 → 文字问答；CC 判断视觉依赖则主动出 mini HTML
        ↓
prototype
  ├─ 语义默认值（来自 PRD AC 或 Step 1 补问）已在原型数据/行为中体现
  └─ 交互层决策（来自 Step 3 对答）已在原型交互中可点击验证
        ↓
TRD
  ├─ 读 PRD（语义默认值在 AC 中，有例子）
  ├─ 读 prototype（交互层决策可见）
  └─ 接口设计无需猜：搜索参数/排序参数/删除接口语义/用户偏好是否入库
```

## 明确不处理

- **draft-ux 跳过时无兜底**：偶发场景，加复杂机制代价过高，接受此风险
- **develop 侧 prototype 未强制读**：develop spec 的既有问题，另行处理
- **第一类边界靠 CC 自判**：任何分类都有模糊边界，不值得为此加规则
