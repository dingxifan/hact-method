# Findings：GPT-5.6 双运行时适配

## 已核对的事实

1. 当前主线仍是 CC 单入口：根 `CLAUDE.md` 与 `templates/CLAUDE.md` 都承担大量启动协议内容，尚无根或模板 `AGENTS.md`。
2. 旧 `origin/codex-runtime-adaptation` 与当前 `master` 的 merge-base 是 `2d313832`，直接合并会覆盖后续方法论演进；仅可借鉴其目录结构。
3. 当前 B 类审查留痕已由 `skeleton/07-status-contract.md`、`templates/scripts/check-sprint.js` 与 `specs-execution/develop.md` 共同要求，待议清单中的“20 包 0 报告”已不是主线现状。
4. 当前批量审查用 `git write-tree` 固定审查快照，已提供比“逐任务 commit”更小侵入的范围固定机制。
5. 当前 B 类升级判据覆盖风险、跨模块逻辑和 API/字段变化，但未明确覆盖已签 TRD、standards、共享类型/API 与共享资产。
6. `.git/hooks/` 不入版本控制；模板脚本与项目副本存在双向漂移风险。解决方向先是可见性与安装验证，不是覆盖项目 hook。

## 设计结论

### 运行时不是任务状态

项目的路由、完成状态和 Gate 只反映工作本身。运行时可作为进度或审查报告的可选出处记录，但不能改变任务的可取性、审查标准或放行结论。

### 入口是确定性选择，能力是动态协商

- `AGENTS.md` 代表 Codex 入口，`CLAUDE.md` 代表 Claude Code 入口；不从模型名、shell 命令或环境变量猜测。
- 启动预检报告各能力为 `available`、`degraded` 或 `blocked`。
- 缺失浏览器或远端通道时，不能虚报验证或部署完成；缺失隔离审查时，不能以同会话复查替代。

### GPT-5.6 的使用边界

- 长上下文用于跨文档语义收敛、V0 as-built 对账、规范一致性审计；不把整仓内容无选择塞入每个实现会话。
- 独立子代理用于只读调研、验证和对抗审查；共享文件的写入仍按资产依赖串行。
- 输出上限不是报告配额；所有长过程要压缩为可检查的证据账本、任务包或审查报告。

### 本轮顺带补格的边界

- B 类只允许 `contract-impact: none`。实现既有已签契约可在 A 类任务包标 `governed`，但任何权威契约修订都先退出 develop，走 `revise-doc` 或新迭代后重新规划。
- 并发资格由写集决定，不由代理数量决定。`files` 或 `asset-writes` 重叠且无任一方向依赖路径时机械阻断。
- V0 对账账本只索引本期触及事实和权威锚，不复制整仓；它补的是证据持久化，不宣称已经解决待议中的“所有地基关注点跨期整体自洽复核”。
- hook 探针只报告 active、tracked、template 三方状态，不自动安装或覆盖。跨项目定期元检查和存量仓分发仍需另行授权。

## 待验证假设

1. ✅ 现行 Codex 支持项目级 `.codex/agents/*.toml` 角色配置；本机 CLI 也确认支持所用沙箱档位。方法论不再依赖旧方案中的嵌套 CLI 进程，实际账号若缺某模型则由预检显式报告并选择已验证的同级替代。
2. 共同启动协议可以从当前 `templates/CLAUDE.md` 抽出，且不改变现有状态推断顺序。
3. ✅ “运行时专属机制词不得进入中立正文”已扩展到执行规范、结构契约、骨架、审查 brief、共同启动和能力接口，运行时映射不在默认扫描范围。
