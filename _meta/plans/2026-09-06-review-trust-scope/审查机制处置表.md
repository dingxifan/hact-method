# 审查机制处置表

依据：[全局重审工作约定](全局重审工作约定.md)。前两批已实施记录减法与接缝职责合并；第三批仅评估粒度，结论为暂不合并审查时点，不新增运行义务。

目标流程：实现者按已确认契约完成改动并自测 → 自动验证提供可复现结果 → 独立审查核契约、实际改动与证据盲点 → 按根因整改并定向复核 → 整合验证组合行为 → 用户裁决业务取舍和需接受的风险。

## 下一批优化范围：Codex 自主开发与用户任务设计（待实施）

用户已指定 Codex 为唯一目标，不再承担 CC 兼容；本节记录本轮讨论要求，不代表执行规范已经改造完成。

- **Codex 执行组织**：评估退役双运行时映射/兼容专属检查；主线可直接实现连续工作，独立且有收益的工作才委派，首次审查须创建不继承实现叙事的上下文。模型配置、验证强度与并行方式按任务性质确定。
- **长程 develop**：一次授权可覆盖较长任务集，内部以可验证工作单元连续推进；压缩、恢复和执行单元切换不要求用户重复确认。复用现有任务、Git、审查和 progress 保存关键决策前提、未关闭问题、验证版本和下一动作。验收跨压缩后是否遗漏约束、重复失败路线、复用失效证据或提前宣告完成；不以压缩次数或持续时长替代质量判定。
- **draft-ux 以用户任务为中心**：先明确用户在什么情境下要完成什么结果、怎样知道已完成，再设计跨功能的完整动线，最后安排页面、控件和功能入口。功能/AC 覆盖作为反向查漏，不再主导画面拆分。

UX 的实施与验收要求：

1. 以用户目标、触发情境、起点、关键判断、完成结果组织 ux-flows；区分「用户任务」与「开发任务包」，允许一条用户任务跨多个功能和页面。
2. 动线须覆盖准备信息、操作/决策、反馈、完成与下一步，以及相关的失败、取消、返回、未保存离开、中断后恢复。只覆盖有业务意义的分支，不穷举所有点击排列。
3. 用连贯的场景数据制作可交互原型；跨页面保留任务上下文、选择与输入，避免每个页面单独展示正确而整条任务走不通。
4. 原型审查须自读 PRD 与用户任务动线并在浏览器中实际执行；核入口是否可发现、信息是否足够、步骤是否多余、反馈是否清楚、异常是否可恢复。只查 prototype-map 中声明的锚点和 onclick 存在不能证明完成。无浏览器证据时明确未完成，不能把结构检查当成动线验收。
5. AI 在交给用户之前完成技术走查与已授权范围内修复；用户评价任务是否符合实际工作及使用体验。重大交互取舍用少量可操作方案比较，不要求用户替 AI 发现死路。
6. 原用户任务与完成条件须经 TRD、任务包 reference 和集成/验收场景持续承接；防止 develop 长程推进时重新退化成逐功能实现。优先调整现有 ux-flows/prototype-map/design 和审查/验证消费者，不新增平行文档、额外 Gate 或另一套规则库。

当前证据：draft-ux 虽已有场景拆解，ux-flows 仍按「功能」组织，最终完成声明统计功能/场景数；prototype-review 明确排除流程顺畅、信息架构及 map 声明完整性。这些是本轮改造的直接落点，优先替换现有职责，而非追加一句理念。

最少输入为权威契约、适用规范、固定改动版本、验证证据；复审加前次独立报告。问题正文只存逐轮报告；状态文件保留结论、报告索引和现有成本汇总。preflight 与恢复记录暂留其既有用途，不新增状态或协议版本。

## 有限验证与边界

以下是前两批验证记录；Standards 专属校验现已退役，当前结果见「Standards 退役」节。

- 普通任务：真实临时 Git 仓的 B 类完整审查，无 profile 模块/JSON、无 status issues，固定改动与报告仍可通过；Foundation 专用 brief 的报告路径同样通过。
- 重要真实缺陷的职责走查：07-08 记录的 JHH RLS 漏写 user_id → sensitive-boundaries 与必要调用链；409 被全局 filter 吞 → contract/test-evidence 与错误处理调用链；单测假绿 → 独立 oracle 与测试证据核实。三者均不依赖 profile 或 status 问题副本，仍有明确检查入口。这里只复核历史记载与现行 brief，未重跑原项目、未测实际模型检出率。
- 重要问题处置的机械验证：错任务、不可解析 tree、错 hash、累积 diff 越出 files、缺规范证据与未关闭 blocking finding 仍失败；目标已闭合及局部契约修订可定向通过，不改写旧报告。
- 中断恢复：旧 full 带 profile 引用可续新 targeted；独立报告前后链错误仍失败。真实 Git/worktree 的 wave 拆前缀通过；缺 preflight 或 commit 内结论未通过仍不能恢复为已通过。
- 兼容：不新建版本协议，旧 profile/内联问题仅保留为历史附件，当前检查器不消费；旧检查器不具备新契约，项目试点必须成组取当前规范/检查器，仍须逐仓授权。本批不改项目仓。
- 自动检查验证可执行约束，文本走查验证职责入口；两者不能证明节时或实际模型召回不变。时间/token 收益未验证。
