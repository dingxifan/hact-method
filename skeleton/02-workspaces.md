# 02 — 工作区

> **本文回答**：v2 有几个工作区？每个工作区是什么"心态"？文件读写权限的边界？
>
> **不回答**：有哪些任务（→ `../tasks/README.md`）；任务状态怎么流转（→ `../protocols/state.md`）。

---

## 1. 三个工作区，按"心态"切割

工作区切的**不是"谁"**——是"做什么类型的事时所处的心智状态"。同一用户可按工作目标进入对应目录；切换目录本身不要求另开会话。
| 工作区 | 心态 | 物理形态 |
|---|---|---|
| **hact-method** | 方法论 | `{工作区根}/hact-method-lab/` |
| **项目根** | 项目 | `{工作区根}/{project-name}/`（项目仓根目录） |
| **hact-notes** | 个人积累 | `{工作区根}/hact-notes-{姓名}/`（可选，不自动创建） |

### 目录约定：同级并列 + 一律相对引用

三类仓**互为同级**，同住一个「工作区根」：

```
{工作区根}/                    ← 位置由各人自定；方法论不假设盘符、不假设目录名
├── hact-method-lab/           方法论仓
├── hact-notes-{username}/     可选个人积累（不要求建仓）
├── {项目A}/
└── {项目B}/
```

**方法论文本里一律写相对路径，不得出现盘符或任何机器专属的绝对路径**——本方法多人共用，各人的工作区根不同，写死即在别人机器上失效：

| 从哪 | 到哪 | 写法 |
|---|---|---|
| 项目仓 | 方法论仓 | `../hact-method-lab/...` |
| 项目仓 | 个人 notes 仓 | `../hact-notes-{username}/...` |
| 方法论仓 | canonical Task / Protocol / template | `tasks/...`、`protocols/...`、`templates/...` |
| 方法论仓 | 某个项目仓 | `../{项目名}/...` |
| 方法论仓 | 成员 notes 仓 | `../hact-notes-{username}/...` |

唯一例外是**记录既成事实的历史档**（`_meta/status-history.md`、`_meta/plans/` 设计稿、`_meta/input/`）——它们描述"当时在哪台机器上发生了什么"，保留原样，不回改。

## 2. hact-method（方法论心态）

**触发场景**：调整方法论 / 跨项目浏览 / 立新项目。

正常任务见 ../tasks/README.md。方法论调整是获用户明确授权后直接处理的发散性工作，不强行预定义 Task 类型（BRIEF 决策 #20）；纯读浏览不创建任务实体。

**文件权限**：
- **工作位置**：方法论仓的 tasks / protocols / runtime / templates 与入口文档；实际写集按本次用户授权。
- **可读**：各项目仓的编排状态（按需）
- **不写**：具体项目的代码

---

## 3. 项目根（项目心态）

**触发场景**：一切与具体项目相关的工作——无论是编排（写 PRD / 规划迭代）还是开发循环（写代码 / 推 PR）。

项目工作使用 ../tasks/README.md 的 canonical Task；B 类先经 ../protocols/b-intake.md 调查。

**物理形态**：项目仓根目录（`{工作区根}/{project-name}/`，与方法论仓同级），代码与协调文件合并存放。

**文件权限**：
- **工作位置**：当前项目仓的代码与协调文件；实际写集仍受 Task Contract 和 Human Authority 限制。
- **可读**：`hact-method` 当前 Task / Protocol / Runtime / template（同一 adopted SHA）
- **不写**：`hact-method` 自身规范、其他项目的目录

---

## 4. 可选个人积累

可用任意已有笔记工具；不要求每人一仓，不由 init-project 自动创建，不是开发/收尾依赖。仅按持有人明确许可访问，见 `../guide/05-个人积累仓管理.md`。

## 5. 跨工作区与规范切换

工作目录不授予写权限。具体项目开发不顺手修改方法论或他人仓；发布、规格修订分别加载对应执行规范并核授权。发现契约歧义时保留当前工作与恢复证据，先完成所需裁决/修订再继续，不因更换规范或上下文压缩自动清空任务状态、强制另开会话。
