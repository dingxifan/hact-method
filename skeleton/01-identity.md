# 身份、负责人与授权

Git author 用于提交归属，不证明用户授权；不建立另一套 web 用户映射、user_disciplines 表或学科准入系统。

## 执行边界

- 任务负责人以 `status.yml tasks[].assigned_to` 为准；认领/移交时核对活跃任务、实际分支和写集，不能覆盖他人在制品。
- 能否操作由当前用户明确授权、仓库权限、保护分支和工具权限共同约束；`discipline` 只是可选知识分类，不授予代码写入、Gate 签署、合并或部署权限。
- 已授权范围内的读写、测试、整改可以自主连续推进。只要求分析/诊断时不擅自实施；业务/产品决策、破坏性操作、对外副作用或部署仍按相应任务边界请求确认。
- Gate 必须有用户明确确认；模型建议不冒充用户决定。敏感改动保留 develop 合并前人工裁决，不因自报身份/学科而跳过。
- 私人资料按其持有人授权访问；不因团队管理员身份推断可以阅读/复制成员私人笔记。

## 协作

状态登记是协作记录，不是跨分支分布式锁。认领前同步权威状态并核实际工作树，冲突写集串行协调；转交记录负责人、分支、未完成项与恢复入口。分支/提交归属不能代替真实资源权限。
