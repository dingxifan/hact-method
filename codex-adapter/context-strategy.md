# Codex 短上下文运行策略

> 本文回答：在 Codex 上下文小于 Claude Code 长上下文的情况下，如何运行 hact-method 而不依赖长聊天记忆。

## 核心判断

hact-method 可以移植到 Codex，但不能原样依赖长上下文。Codex 版必须把长上下文红利改造成：

- 文件化交接
- 精确行号引用
- 分片加载规范
- 外部检查器
- 任务结束写回

## 基本原则

### 1. 重要信息必须落盘

以下信息不能只存在于 CC 或 Codex 对话里：

- 用户拍板的产品边界
- 技术栈选择
- 安全项强制边
- 任务拆分理由
- 任务阻塞原因
- 测试降级说明
- 审查建议级遗留项

推荐落点：

| 信息 | 推荐落点 |
|------|----------|
| 项目级决策 | `decisions.md` |
| 当前任务进度 | `_meta/sessions/{task}-progress.md` |
| 地基和跨切面约束 | `foundation.md` |
| 开发任务边界 | `queue/{task-id}.md` |
| 跨期风险和偏离 | `backlog.md` |
| 方法论反馈 | `feedback.md` |

### 2. Codex 不默认读全文

Codex 执行任务时按以下顺序加载：

1. 当前 handoff 包。
2. 当前任务包全文。
3. 任务包中 `reference` 指向的行号范围。
4. 任务包中 `relevant-standards` 指向的章节。
5. 相关代码文件。
6. 测试结果或 `git diff`。

只有在引用不足、测试失败无法归因、或发现上游矛盾时，才扩展读取范围。

### 3. 长 spec 拆成短卡

Claude Code 版 `specs-execution/*.md` 可以很长，因为它面向长上下文会话。Codex 适配层应使用短流程卡：

| 场景 | 短卡 |
|------|------|
| 写代码 | `specs/develop.codex.md` |
| 独立审查 | `specs/review.codex.md` |
| 方法论修改 | `specs/method-change.codex.md` |
| 一致性扫描 | `specs/consistency-check.codex.md` |

短卡只放当前场景的步骤、输入、退出条件。长解释、历史决策、其他 source 分支不在启动时加载。

### 4. 审查只读权威原文

Codex 做独立审查时，输入只能来自：

- 任务包
- PRD/TRD 精确引用
- standards 精确章节
- `git diff`
- 测试代码和测试结果
- review brief

不读取执行者总结、不读取执行者自评。否则审查会被执行叙事锚定。

### 5. 退出前必须写回

Codex 每次任务结束前必须输出或写回：

- 读取了哪些权威文件。
- 修改了哪些文件。
- 跑了哪些验证。
- 哪些验证未能运行及原因。
- 是否发现上游文档问题。
- 下一个执行方应做什么。

若接入正式项目流程，这些信息应写入 `_meta/sessions/` 或对应任务包 / `status.yml`。

## expand-read 协议

Codex 初始只读最小上下文。出现以下情况时允许扩大读取范围：

| 触发 | 扩大读取范围 |
|------|--------------|
| reference 行号不存在 | 读取目标文件附近上下文，再报告引用失效 |
| standards 章节缺失 | 读取 standards 目录索引或全文，找最近相关章节 |
| 测试失败无法归因 | 读取失败栈相关文件和最近改动 |
| 任务包 AC 与代码现状矛盾 | 读取 PRD/TRD 对应段落 |
| 发现疑似上游设计缺口 | 停止执行，输出 revise-doc 建议 |

扩大读取后仍不能确定，不继续猜测实现。

## 不变边界

Codex 不应在短上下文执行中顺手改这些内容：

- 已签 PRD/TRD 的语义。
- Gate 签字。
- 安全敏感改动的最终合并裁决。
- 与当前任务无关的大范围重构。
- 方法论主体目录，除非任务明确是 method-change。

## 成功标准

一次 Codex 任务执行被视为上下文管理合格，需要满足：

1. 不依赖未落盘的聊天记忆。
2. 读取范围可以被解释。
3. 修改范围与任务包一致。
4. 验证结果可复现。
5. 下游接手者无需追问“刚才你为什么这么做”。

## 失败信号

出现以下情况，说明上下文策略不合格：

- Codex 引用了 handoff 包里没有的用户口径。
- Codex 修改了 reference 之外的大量文件但没有说明。
- Codex 审查时复述执行者总结，而不是引用 diff / standards。
- Codex 因为没读到长 PRD 而漏掉 AC。
- Codex 在不确定上游语义时继续实现。

这些情况应触发协议修正，而不是只修单个任务。
