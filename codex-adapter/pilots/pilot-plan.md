# Codex Adapter 试点计划

> 本文件定义 Codex 适配层的试点顺序。
> 目标是先验证交接和短上下文协议，再决定是否回填正式方法论。

## 试点原则

1. 不修改现有 Claude Code 方法主体。
2. 先人工切换，不做自动编排。具体操作步骤见 `README.md` 「人工交接怎么操作」——交接包必须先落盘为文件，Codex 开场指令只指路、不重复口头背景。
3. 每个试点只验证一个能力。
4. 每次试点结束后记录评估结果。

## Pilot A：方法论仓结构化修改

### 目标

验证 Codex 是否适合对 hact-method 做局部、结构化、可验证的文档修改。

### 任务例子

- 补一个 Codex 适配层文件。
- 修正某个 guide 中的旧术语。
- 扫描某个 task type 的悬挂引用。

### 成功标准

- 只修改指定文件范围。
- 能说明修改原因。
- 能用 `rg` 或 diff 验证无越界。
- 不误改现有方法主体。

## Pilot B：独立审查

### 目标

验证 Codex 是否能作为独立审查员，只凭权威原文发现问题。

### 输入

- review handoff。
- 一个已有任务包。
- 一段 diff 或 PR。
- standards 相关章节。
- 测试结果。

### 成功标准

- findings 有证据。
- 不复述执行者自评。
- 能区分阻断和建议。
- 不试图替代 Gate 或安全裁决。

## Pilot C：单个 develop 任务

### 目标

验证 Codex 是否能按 handoff 完成一个边界清晰的开发任务。

### 输入

- develop handoff。
- 一个小任务包。
- 明确 allowed files。
- 明确测试命令。

### 成功标准

- 代码实现 AC。
- 测试 / lint / build 结果清楚。
- 修改范围受控。
- 能输出 CC 可接回的结果。

## 推荐顺序

1. Pilot A
2. Pilot B
3. Pilot C

原因：先验证低风险文件修改，再验证审查，最后验证写代码。
