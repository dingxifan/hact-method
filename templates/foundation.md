# 地基蓝图 · {项目名}

> 本文件是全项目「跨切面地基」的唯一参照：有哪些候选关注点、哪些获准在 V0 一次性立住、强制边达到哪一档、核心领域模型长什么样。
> 由 `init-project` 的「项目共识讨论」步生成初稿（读 `_meta/input/` 背景材料、**只摸全貌与领域模型，不列功能**），下游消费：
> - **V0 走骨架**（`draft-foundation` 地基设计 + `develop` source=foundation）只处理通过 V0 准入门槛的行；其余留给 V1+ 随真实功能建立；
> - **draft-prd** 功能挂「一、领域地图」的核心实体；**draft-ux** 在 V0 已建视觉框架时填真值，否则随 V1 建立。
> **活文档**：init 播种，后续只维护当前关注点与声明；不追加事故过程或版本叙事。含糊项留空，等开发中“跳出地基”再提拔；新关注点由 `draft-tech-design` 登记、`plan-sprint` 拆跟进包、develop 建。
> **按项目风险伸缩**：预置行只是候选清单，不是 V0 待办。只有「已证明跨切面 + 稳定 + 晚建会横切多层/数据或扩大安全风险 + 一根薄切片可证明」才标 `V0`；否则标 `V1+`。完成判据不是把表填满。
>
> **成功度量（命门）**：正常开发顺手写出的代码有多大概率合规？让默认路径满足规范，并拦住常见遗漏。「二」表按关注点风险确定应有档，达到约定档位即可；不以持续升档或消灭一切绕过可能为目标。
> **"合规"= 开发质量的全部维度，不止数据安全**：命门量的是任一该守的规范（响应格式 / 分页 / 错误信封 / 视觉 token / 四态 / 命名……）被顺手偏离的概率；数据隔离只是后果最可见的一个实例。随规模复利失控的不是某一处安全，而是这一整套质量保证的"档位"松动——N 个开发者 × M 个迭代各走一次省力路，每条停在人审级的边都漏一点。**所以地基层是通用的质量结构化机制，不是安全专用机制。**
> **强制边的信任前提**：按方法论 `templates/review-briefs/review-scope.md`，开发人员可信但会犯错；验证规范合规、正常开发误用防护及外部风险防护。
>
> **真构造级 = 正常路径由平台/数据库等机制强制满足不变式**：DB 行级安全 / 框架全局守卫·管道 / 路由组外壳使常见遗漏不致静默违规；仅靠“记得用 helper / base 类”仍是弱边。没有现成平台瓶颈时，用公共入口与 lint/类型约束常规接入，按范围内正反例验证，不追求对任意源码改写不可绕过。

## 二、地基关注点登记 + 强制边诊断

> 一张表管到底（不在别处重复）。**技术内生**几行已预置（任何这个栈的应用都有），讨论时勾选/删减；**领域涌现**从「一」补进来。
> - **形式**：说它（共享类型）/ 穿过它（单例瓶颈）/ 住进它（外壳）/ 被它笼罩（环境基线）/ 往里填（脚手架）——决定于"业务代码怎么碰它"。
> - **应有档（init 立 bar）**：构造级（正常路径强制满足不变式）> 机械级（常见违规触发检查失败）> 人审级（靠人看），按关注点风险选定。
>   ⚠️ **安全敏感项（数据隔离 / 鉴权 / 越权）应有档 = 构造级，不可议价**——成熟项目实证：bar 不在上游立，再好的团队也默认滑到手写弱边、漏一行就泄数据。
> - **阶段/实际形式·档**：init 先写 `V0` 或 `V1+`。V0 行由 `draft-foundation` 补 `{具体形式}（{档级}）`；V1+ 行写推迟理由，等真实功能触及时由 `draft-tech-design` 补实际形式。foundation-review 只验 V0 行；安全敏感且确实存在的约束不得借标 `V1+` 规避。
