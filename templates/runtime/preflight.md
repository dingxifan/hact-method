# 运行时任务能力预检

> 共同启动协议已完成代码同步、`task.type` 推断和单份任务规范加载。此预检只核该任务实际需要的能力；通过后才执行任务动作。

## 1. 声明运行时

入口文件确定本会话运行时：`AGENTS.md` 声明 `codex`，`CLAUDE.md` 声明 `cc`。不得根据模型名称、命令路径、环境变量或聊天内容猜测；入口缺失或同时被手动混用时，停止并要求人工显式选择。此处复述入口结论，不重复探测。

输出固定起始块：

```text
📋 会话启动·运行时预检
- 运行时：{codex | cc}
- 入口：{AGENTS.md | CLAUDE.md}
- 映射表：templates/runtime/{codex | cc}.md
- 当前任务：{task.type；develop 同时写 source}
```

## 2. 协商能力

从已加载的单份任务规范提取实际动作，只检查这些动作命中的能力：隔离审查、隔离执行、只读调查、浏览器场景、远端命令、代码托管、检查器与门卫。命中项标记为 `available`、`degraded` 或 `blocked`，并说明依据与下一步；未命中的能力不输出、不探测。

任务命中「检查器与门卫」时，若项目存在 `scripts/check-hook-state.js`，运行 `node scripts/check-hook-state.js --method-root ../hact-method-lab`：

- 退出码 0：tracked 门卫已由实际生效 hook 逐字节安装或明确委托，且方法论模板无漂移，标为 `available`。
- 退出码 1：按 `signals` 报告未安装、active↔tracked 漂移或 template↔project 漂移，标为 `degraded`；继续时手动运行本任务相关检查器。只报告，不自动复制或覆盖项目自定义 hook。
- 脚本不存在（存量仓）：标为 `degraded` 并提示补铺；不虚报门卫已生效。

本检查只让本地状态可见，不把 pre-commit 冒充安全边界；`--no-verify` 仍可绕过并须自行留痕。

```text
- {本任务所需能力 1}：{状态} — {实现或阻断原因}
- {本任务所需能力 2}：{状态} — {实现或阻断原因}
```

没有命中任何可选能力时写「所需可选能力：无」，不得为填满清单探测无关能力，也不得把未检查项伪装成 `available`。

## 3. 处理结果

- 存在与当前任务直接相关的 `blocked`：在该边界停止，说明缺失能力、不可替代原因和需要的人类动作。
- 仅有 `degraded`：写明顺序替代方式后继续；不得把加速能力缺失写成质量通过。
- 全部所需能力可用：进入当前任务执行。

如需保留出处，写入本会话进度或审查报告的 `runtime_context`；不改任务状态、Gate 或任务包字段。
