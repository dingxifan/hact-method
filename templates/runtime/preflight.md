# 运行时启动预检

> 此预检是共同启动协议的第一段；完成后才执行代码同步、状态推断和单份任务规范加载。

## 1. 声明运行时

入口文件确定本会话运行时：`AGENTS.md` 声明 `codex`，`CLAUDE.md` 声明 `cc`。不得根据模型名称、命令路径、环境变量或聊天内容猜测；入口缺失或同时被手动混用时，停止并要求人工显式选择。

输出固定起始块：

```text
📋 会话启动·运行时预检
- 运行时：{codex | cc}
- 入口：{AGENTS.md | CLAUDE.md}
- 映射表：templates/runtime/{codex | cc}.md
```

## 2. 协商能力

按当前任务可能需要的能力检查：隔离审查、隔离执行、只读调查、浏览器场景、远端命令、代码托管、检查器与门卫。每项标记为 `available`、`degraded` 或 `blocked`，并说明依据与下一步。

「检查器与门卫」在此只做初判；共同启动协议 Step 0.5 会在方法论同步后用项目脚本核 active hook、tracked 脚本与方法论模板三方状态，并用实测结果更新该项。

```text
- 隔离审查：{状态} — {实现或阻断原因}
- 浏览器场景：{状态} — {实现或阻断原因}
- 远端命令：{状态} — {实现或阻断原因}
- 代码托管：{状态} — {实现或阻断原因}
- 检查器与门卫：{状态} — {实现或阻断原因}
```

未被当前任务使用的能力可标记 `not-required`，但不得伪装成 `available`。

## 3. 处理结果

- 存在与当前任务直接相关的 `blocked`：在该边界停止，说明缺失能力、不可替代原因和需要的人类动作。
- 仅有 `degraded`：写明顺序替代方式后继续；不得把加速能力缺失写成质量通过。
- 全部所需能力可用：进入共同启动协议的代码同步与状态推断。

如需保留出处，写入本会话进度或审查报告的 `runtime_context`；不改任务状态、Gate 或任务包字段。
