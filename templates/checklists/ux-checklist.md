# 交互质量自检清单（draft-ux 阶段）

> 在 draft-ux 的 Step 3.5 由陌生 subagent 对原型逐条冷审，输出【交互质量走查报告】。
> 目标：以"第一次来的用户"视角挑刺，找出设计本身的缺陷——不是确认流程走得通，而是确认它好用。
> 每条必须用原型里的具体产物回答；答不上来 = 这处设计缺失，记 ❌。标 ✅/❌/N/A。

**边界**：本清单只管结构/交互层（信息架构、状态、反馈、容错、任务连贯）。
视觉规格（字体字号、间距、配色、圆角）归 `design.md`，不在此重复。
与 develop 阶段 frontend-checklist『十一·设计保真』不同——那查"代码是否忠实实现了设计"，本清单查"设计本身是否完备好用"。

## 一、起步与可发现性
- [ ] 第一次来的用户进入每个主要页面后，能否一眼看出"这里能做什么、从哪开始"？
- [ ] 每屏是否有且仅有一个视觉上最突出的主操作？多个同等操作是否真的合理？
- [ ] 核心功能入口是否在用户预期位置？有没有藏在需要先知道才找得到的地方？

## 二、状态完备（每个数据区都要回答三态）
- [ ] 每个列表/数据区的"空状态"长什么样？首次无数据 vs 筛选无结果是否区分？
- [ ] 加载中给什么反馈？（骨架屏/loading，而非白屏）
- [ ] 出错时用户看到什么？能否知道发生了什么、下一步怎么办？

## 三、操作反馈与确认
- [ ] 每个操作执行后，用户怎么知道成功了？（提示/状态变化/列表刷新）
- [ ] 破坏性/不可逆操作（删除、提交、清空）是否有二次确认或可撤销？
- [ ] 耗时操作是否有进度/禁用反馈，避免重复点击或以为卡死？

## 四、容错与回退
- [ ] 走错路径时能否方便回退（返回/取消/面包屑）且不丢失已填内容？
- [ ] 表单校验失败是否定位到具体字段并说明怎么改，而非笼统报错？
- [ ] 是否存在"进得去出不来"或"必须重头再来"的死胡同？

## 五、任务连贯性
- [ ] 完成一个任务后，用户自然想做的下一件事，界面是否提供了顺畅入口？
- [ ] 多步流程中，用户是否始终知道"在第几步、还剩几步、能不能回上一步"？
- [ ] 跨页面操作链路是否连贯，没有"要用户自己记住信息再手动跳转"的断点？

## 输出格式
```
【交互质量走查报告 · v{N}】
✅ 通过：XX / XX（N/A：XX）
❌ 发现（每条：视角 / 画面 / 问题 / 建议）：
  1. [清单·状态完备] {画面}缺"筛选无结果"空态 → 建议补
  2. [第一人称] 提交后停在空白页，无下一步入口 → 建议加返回列表
待主会话判定：[改原型 / 记待办 / 属过度]
```
