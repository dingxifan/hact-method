# 原型用户任务独立审查

由主线以 Codex 空历史子代理创建（本接口 fork_turns="none"），不得继承设计过程、自评或方案辩解。直接执行本文，不重新启动项目、同步 Git 或认领任务。

## 自读输入

本目录 review-scope.md；本期 PRD、ux-flows.md、prototype.html、prototype-map.md、相关 design 页面及浏览器证据。PRD 和用户目标是判断依据，map 是待核声明，不能当完备性真相。

## 检查

- **任务成立**：目标是否是真实用户结果，起点/信息/判断/完成反馈是否连贯；功能是否有合理位置，不要求每功能单独一页。
- **层级与落点**：对照动线—界面地图核主入口、主任务落点、返回位置和辅助分支归属；共用组件的不同模式不能混淆作用对象或返回上下文，未经确认不能用自动打开某个子对象代替用户选择。
- **覆盖完整**：从 PRD 独立核 AC 的覆盖与排除，找漏声明；核重要替代路径、失败、取消和恢复，而非穷举输入排列。
- **契约回写**：若 UX 自行决定对象创建时点、全失败/部分成功、重试保留或自动选择等用户可观察规则，而 PRD AC 没有依据，按 scope-gap 阻断并回到 PRD，不把原型当需求真相源。
- **实际可用**：浏览器中从真实入口重走每个核心任务的主路径与高影响失败/恢复分支，其余复用有效证据。检查入口可发现、信息先后、冗余步骤、重复输入、跨页上下文及结果可理解；不能只看 onclick、href 或节点存在。
- **证据有效**：实际原型版本与证据相符；更改状态逻辑后旧通过记录不可直接复用。没有浏览器能力或必要分支未执行则记录未完成，不能用静态检查放行。
- **范围**：核已确认的视觉和交互约束；审查可操作性、理解成本与任务障碍，不替用户决定审美或业务方向。新增业务需求须回 PRD/用户裁决。

报告仅写 findings、必要执行证据和未完成项，落 prototype-map 的「独立审查」段；证据文件复用 ux-evidence。每个问题给 U/S、复现动作、实际/预期结果与影响。真实死路、信息缺失导致无法决定、结果错误或必要恢复失效可阻断；优化偏好作建议。无发现写 findings: []，不重抄映射或生成逐项空报告。
