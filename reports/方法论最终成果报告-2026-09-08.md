# HACT 方法论瘦身与 Codex 化：最终成果报告

日期：2026-09-08
方法内容基线：`codex/context-reduction@2e9ed33`
报告口径：只列最终保留的规则、退役的机制、承接职责和交付边界；不复述讨论往复。分发工具与本报告作为本批收尾附件单列，不混入此前方法内容的增删统计。

## 一、结论

最终版本保留规格驱动和独立质量验证，将执行环境收敛为 Codex，并削减重复加载、重复记录、无效停顿和过度证明。

核心变化有六组：

1. **少教通用写法，保留项目承诺和禁区**：三个 Standards 及其生成、匹配、回填、使用审计全链退役；有效独有约束归回现有权威对象。
2. **少做无关审查，保留独立判断**：开发人员可信但会犯错；审当前规范、普通错误和外部风险，不证明工程规则能抵抗拥有源码修改权的恶意开发者。
3. **减少执行交接与合法停点**：主线可实现，已授权任务集内自动接续；压缩、批次结束和进度询问不自动终止开发。
4. **以用户任务组织 UX**：先明确用户要完成的结果和完整动线，再安排页面与功能；同一任务贯穿设计、开发与验收。
5. **减少管理附加链**：个人笔记、收割、学科准入、成本计时和强制清空归档退出交付必经条件；动态状态只维护一份。
6. **保留 A 类主干，轻量化 B 类**：A 类 PRD→TRD→任务规划及 G1–G5 顺序不变；B 类允许先调查代码、写最小问题/预期/验证契约。

这不是“取消规格、取消独审、取消测试”，也不是已经证明开发耗时下降。已完成的是规则与配套实现；真实节时、漏检率及跨压缩保持率仍需项目运行样本。

## 二、最终的职责与权威对象

| 要回答的问题 | 最终权威对象 / 责任 |
|---|---|
| 用户要做成什么、本期不做什么 | PRD、已确认用户意图和 AC 的 intent/oracle |
| 用户如何从起点走到结果 | ux-flows 的用户任务/场景、可交互原型及 design 页面规格 |
| 接口、数据、状态和错误如何承接 | TRD 与共享契约 |
| 哪些跨切面条件不能被破坏 | Foundation 不变量及实际强制边 |
| 本项目选了什么技术、怎样验证 | project.md 技术层与已有 scripts/config/CI |
| 当前开发任务负责什么、不负责什么 | 任务包范围、reference、files、asset-writes、depends_on、do-not |
| 谁在做、做到哪、对应什么 PR/Gate | status.yml；不从聊天或旧 Markdown 状态推断 |
| 实际审了哪个版本、问题如何闭合 | 固定 Git base/head、diff hash、逐轮报告与 finding 链 |
| 中断后从哪里继续 | 原始契约 + 实际 Git + 有效报告 + 现有 progress |
| 哪些事情只能由人决定 | 业务/产品承诺、实质范围变化、敏感风险接受、部署和真实外部副作用授权 |

正向结果与禁区互补：do-not 不能代替“必须完成什么”，测试不能代替原始用户意图。

## 三、各阶段最终做法

### 1. 初始化与 V0

- V0 不默认启动，必须有已证明跨切面、约束稳定、晚建代价高且可用薄切片验证的事项。
- 只建设获准的最小地基件与一根参考切片，不要求凑齐全栈、所有预置关注点或全部技术基础设施。
- 尚未入选的关注点留 V1+；仅因“V1 将会用到”的运行器、黄金样本、业务能力不成为 V0 交付。
- 范围超过一个正常中型 develop 任务时继续删减；仍无法收敛则跳过 V0，不设无依据的工时/比例硬阈值。
- 走 V0 时保留 G2(v0)、适用安全约束和 foundation 独审；审查只覆盖获准行及真实正反证据，不审未获准的 V1+ 建设。
- 立项不再为每位成员创建、登记私人 notes 仓。

入口：[init-project](../specs-execution/init-project.md)、[draft-foundation](../specs-execution/draft-foundation.md)。

### 2. PRD、技术设计与任务规划

- 清晰、同模块的需求可以成组确认；有歧义或敏感取舍时保留必要人类判断。
- 机械步骤不逐步播报，已明确的信息不重复访谈；不以缩短对话为由省略真实决策。
- 保留稳定 AC 引用、逐条覆盖、内容忠实性和共享资产归属检查；编号存在不等于语义承接。
- intent/oracle 高于派生 example；只有经独立复算的 golden=true 承担字面测试义务。普通例子错误修例子或规格，不让业务实现迁就错误答案。
- 结合已有代码、V0 实况及适用 as-built 记录核对，仅规划本期 delta；不把已实现能力重新拆成新建设任务。新增任务/审查证据协议显式版本化，存量兼容不等于免除新任务要求。
- PRD/技术设计/任务包各自的独立审查职责保留，不以“模型更强”或“下游还会审”替代。
- G3 默认整批审查；只有超过有效上下文范围才按业务模块分批，最后核全局 AC、共享资产和依赖，取消按固定包数切审。
- design 采用全局基线与相关页面锚按需加载；存量未具备稳定页面结构时允许明确的全文兼容，不批量改写旧任务。
- 当前普通 A 类仍在整期 TRD/G3 就绪后开发；没有落地“边开发边决定业务承诺”或取消 G2/G3 的新流程。

入口：[draft-prd-vN](../specs-execution/draft-prd-vN.md)、[draft-tech-design](../specs-execution/draft-tech-design.md)、[plan-sprint](../specs-execution/plan-sprint.md)。

### 3. 用户任务中心 UX

- 从目标、触发情境、起点、关键判断和完成结果组织用户任务，再安排页面和控件。
- 用户任务 U-id 与场景 S-id 不等于开发任务包；允许一个用户任务跨多个功能/页面，也允许一个页面服务多个任务。
- 覆盖有业务意义的失败、取消、返回、未保存离开、重试和中断恢复，不穷举所有点击排列。
- 原型用连贯数据保持跨页上下文；“按钮能点”与“用户任务能完成”分别判断。
- AI 在交给用户前先在浏览器中实际走查；用户负责体验、真实工作方式及重大交互取舍，不替 AI 发现基础死路。
- 原始用户任务与完成条件通过 TRD、任务 reference、联调和验收持续承接，不在开发拆包后退回功能点堆放。
- 取消前端场景数量的固定上限。涉及用户任务变化或视觉基线的迭代，完整浏览器验证不能作为可省选项。

入口：[draft-ux](../specs-execution/draft-ux.md)、[prototype-review](../templates/review-briefs/prototype-review.md)、[UX 产物契约](../specs-structural/draft-ux.md)。

### 4. develop 的长程自主执行

- 一次授权可以覆盖明确的任务集；内部按依赖选当前可验证单元，完成后自动继续余下已授权工作。
- 指定 layer 不自动等于授权清空队列；新增任务、契约变化和部署仍需对应授权。
- 主线直接实现是正常方式。只有独立、工作量足够且有收益的调查/实现才委派，不按文件数或包数机械派发。
- 主线负责实现返回→独审→整改→复审→必要全量/集成→合并→状态与必要缺口移交，不能把阶段性成功当任务完成。
- 进度询问后继续原任务；普通可恢复问题由主线补证处理，不把子代理的 blocked 原样甩给用户。
- 压缩由运行环境管理，不在固定步骤强制 compact，不按压缩次数决定停止。恢复时核原文、实际改动、有效证据、未关闭问题及下一动作。
- 复用现有 progress 和审查记录保存授权范围、关键决策前提、否定路径、活跃单元和尝试次数，不新增 autopilot 或 continuous-execution 账本。
- 复审/恢复不清零累计轮次；达到既有失败上限或真实人类边界才暂停。

共享写集仍须协调；独立并行代码工作使用独立 worktree，不把共享数据库、端口和生成物误当已隔离。single-operator-wave 保留逐任务 preflight、实现、独审和 accepted commit，仅在适用条件满足时合并末端；整组恢复、敏感升档拆分与真实 Git 校验保留。

入口：[develop](../specs-execution/develop.md)。

### 5. 独立审查与验证减负

- 审查重点是适用规范、当前错误、正常误用和实际外部风险；假设可信开发者故意关闭检查或构造规避代码，不形成无限阻断或自动加固欠账。
- 首次独审明确使用不继承实现历史的上下文；当前支持的接口显式 `fork_turns="none"`。工具不支持时报告缺口，不用同一上下文自审冒充。
- review profile 的强制 JSON、生成器、分区/版本/继承校验和专属测试整体退役。审查员按原始契约和实际改动选择范围，不另外生产维度清单。
- 首轮 full，整改默认 targeted；新增文件/模块或局部契约修订本身不强迫全审。只有先前结论广泛失效且无法局部核实时才升级。
- 每任务累计 3 个代码审查轮次后若仍需继续，暂停并按根因修订设计或请用户裁决；第三轮通过则正常收尾。换 finding、根因、会话或工作树不清零。
- 取消逐字段报告、行数自证、逐维度“无发现”、重复覆盖表和独立自检报告义务。仍检查有限契约清单，不把报告减负等同于少查字段。
- 测试期望来自独立契约，不能从被测 schema/实现复制答案。未变共享 schema 的消费者不重复整套字段证明；库通用行为验证接线正反例即可。
- 复用同版本、适用环境和覆盖面仍有效的证据；有新改动、失败或具体疑点才补跑。整改主要验证反例与受影响回归，最终交付仍有必要整合验证。
- 固定 base/head、真实 Git 对象、diff hash、changed-files、报告链和 finding 闭合继续检查；成本时间改可选，不补估、不强制连续对齐，不因计时缺失阻断。

入口：[review-scope](../templates/review-briefs/review-scope.md)、[develop-review](../templates/review-briefs/develop-review.md)、[round 模板](../templates/review-briefs/develop-review-round.md)。

### 6. 组合验证、验收与 G5

- 末端独立接缝派审、专用 brief 和独立报告退役，其职责并入已有联调：准备时核归属、共享定义与退役，执行时验证真实调用路径和终态。
- 组合阻断未解决不能进入验收；仅有 owner 或补缝任务不算解决。原包独立合规时不因组合补缝被打回完整重审。
- 证据写现有联调 result，按版本与变化面复用，不另开接缝审查轮数。接受静态核对后移到合并后联调、减少一个独立视角的取舍。
- 联调默认轻量穿透，真实外部边界按需要与授权验证；用户任务/视觉基线变化须完整档浏览器验证。
- 人工验收保留用户业务和可视体验判断；不可视区已有有效测试证据不重复要求人手验。不能把降级验证算成原 AC 已通过。
- G5 保留必要收尾和明确人签。未闭合开发/修订任务、重要偏离和本期承诺缺口仍需处理，退役实体有实际结论或保留理由。
- feedback 可以保留并引用去向，不以清空证明处理；其他迭代“开发中”文字不阻断本期。project 只更新实际变化，未部署不标已上线。

入口：[generate-integration-tests](../specs-execution/generate-integration-tests.md)、[manual-test](../specs-execution/manual-test.md)、[wrap-up-iteration](../specs-execution/wrap-up-iteration.md)。

### 7. B 类局部开发

- 先只读调查代码、调用方、复现和已有契约，再写“问题→预期→验证”短包，不先猜文件、不重复问卷、不套全部 A 类规划字段。
- 不要求 module/sprint/delivery 等 A 类元数据或凑 AC 条数；保留原始依据、写集、风险、依赖和真实禁区。
- `none` 不夹带共享契约；已有明确意图下的局部兼容 API/公共类型/事件变化可用 `governed`，必须说明调用方、共享写集及兼容验证。
- 破坏兼容、数据库迁移/DDL、业务或权限重定义、与已签规格冲突，不借 governed 自动放行；先处理上游决策。
- 已授权修复时派短包后直接衔接 develop；只要求诊断时不擅自实现。hotfix 是优先级，不取消独审、实际验证或发布授权。

入口：[dispatch-new](../specs-execution/dispatch-new.md)、[B 类检查器](../templates/scripts/check-b-task.js)。

## 四、退役机制清单

| 退役/取消的默认义务 | 最终承接 |
|---|---|
| 三个 Standards、公共/栈候选库和规则生命周期协议 | 现有业务契约、Foundation、project、do-not、真实 check/test/config |
| relevant-standards、standards_checked、retention 配套 | 不再生成/回填；历史字段只保留，不由新版消费 |
| 方法论自有 skills 层及手动 B 类旁路 | 共同 develop、连接脚本、普通 Gitee 操作文档 |

| 末端独立接缝审查及专属产物 | 联调准备与真实路径验证 |

| 计时闭合门、feedback 清空门、数量归档门 | 必要质量证据、实际任务闭合和按需整理 |

学科名称可保留作知识索引，不授予权限。reusables 只索引有价值且不易发现的共享入口；登记路径真实性仍检查。重要决定保留理由与确认依据，不逐任务登记流水账。私人仓及历史数据未因此删除。

## 五、单源状态、迁移和分发

status.yml 维护任务状态、负责人、分支、PR 与 Gate 签署；任务包是契约，sprint 是规划索引，不再维护实时状态列。旧 gates/b-tasks 可作历史，不生成新副本。status-only 签署或新 merged 提交仍路由到对应 Gate/审查检查，避免删副本后丢失检查触发。

本次提供 [sync-method.cjs](../scripts/sync-method.cjs) 与 [逐仓使用说明](../guide/07-同步方法论.md)。脚本按固定版本创建独立 worktree，已知模板自动更新、未知自定义文件生成候选；各仓 Codex 接着完成约束迁移、活跃引用和 hook 接线，不能停在复制完成。验证和本地提交后立即回收临时 worktree，分支与提交保留；默认不推送或部署。

存量升级必须是“约束、入口、检查器、状态和活跃消费者”一起迁移。不能只拉方法论分支或只删 Standards，也不能把所有旧报告重写成新版格式。配置与 hook 不覆盖，实际有效调用链要验证，包括标准 Husky 转发。已提交的干净临时分发 worktree 不等待 PR 合并，只有未提交在制品可以带明确负责人和恢复入口保留。

Codex 入口/角色配置已按 OpenAI Docs 核对：项目自定义代理位于 `.codex/agents/`，配置覆盖与继承有明确优先级；`AGENTS.override.md` 可能遮蔽同层 AGENTS。分发保留项目明确配置，不改变用户全局权限。[代理配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[入口规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

## 六、最终保留与暂缓的边界

- A 类整体滚动规格重构暂缓，整期 TRD/G3 前置未取消；各阶段独立审查时点没有合并。
- 业务/安全/数据契约、原始 AC、独立审查、敏感人工裁决和真实系统验证保留。
- 不扩大生产发布、真实外发、删除数据或跨仓写入授权；解释/诊断不等于实施许可。
- 不承诺宿主退出后自行重启或无限后台执行；长程规则约束已运行任务的接续和恢复。
- 不因历史通过记录假定当前版本仍通过；不从提交时间、审查轮数或“全绿”比例推断真实节时和模型优劣。

## 七、维护量与验证口径

以改造前基线 `7c28db4` 对方法内容快照 `2e9ed33` 做一次最终 Git diff，不累加中途提交，避免往复修改重复计数：

| 类别 | 新增行 | 删除行 | 净变化 |
|---|---:|---:|---:|
| 正文、模板与配置 | 1,257 | 4,235 | −2,978 |
| 检查脚本 | 1,435 | 614 | +821 |
| 测试与夹具 | 1,373 | 435 | +938 |
| 计划、状态与过程记录 | 2,118 | 9 | +2,109 |
| 合计（161 个变更路径） | 6,183 | 5,293 | **+890** |

因此不能宣称“全仓代码行数净减少”。结果是运行正文显著收缩、检查与回归能力增加、历史记录仍有体量。过程记录不属于日常执行全文加载对象；行数也不等于 token、耗时或收益。分发工具、工具测试、本报告和本批文本对齐另算收尾交付成本，不混入上述内容基线。

分类顺序：`_meta/`、STATUS 及根计划/进度记录先归过程记录；其余路径含 test/fixture 归测试；其余 `.js/.cjs/.sh/.ps1` 归脚本；余下归正文/模板/配置。可用 `git diff --numstat 7c28db4 2e9ed33` 复算。

方法内容已有 14 组脚本回归，覆盖真实 Git 快照/审查链、共享写集与依赖、wave/worktree 恢复、用户任务引用、B 类边界、Codex 配置、Gate 与实际 shell 路由。UX 另有虚构原型的浏览器正反例。分发工具测试使用自有临时 Git 仓，不修改六个真实项目，也不连接生产环境。
