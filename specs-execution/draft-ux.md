# exec: draft-ux

> AI 加载本文时，当前任务是从 PRD 出发，**以交互工程师身份**消化业务、构思画面、产出可交互 HTML 原型，为 TRD 提供业务依据。
>
> **角色姿态**：AI = 交互工程师；用户 = 客户。客户只参与上游业务沟通 + 下游设计稿走查，中间过程内部消化、不外露。

**上下文密度**：低-中。PRD 完整时只做缺口扫描、不重复访谈；内部消化不外露，最终交付 HTML 原型供用户走查。

---

## 红线

- **禁止跳过场景拆解和流程穿线直接出原型**：AI 内部消化必须穷举场景、连通流程，再生成画面
- **禁止只覆盖主路径**：所有替代路径（用户选择不同操作 / 不同入口）都必须在场景中穷举
- **禁止死路**：流程图分支必有明确去向；原型无死锚点（`href` 必有目标）
- **禁止系统内部逻辑混入**：场景和流程图只描述用户可见的操作与反馈，后端校验逻辑不出现
- **禁止让用户审查工作过程产物**：场景文字、流程图拓扑、ASCII 线框等需要"文字→画面"转换的产物不外露；对答只用中间产物（mini HTML / 小原型）或最终原型
- **禁止视觉创新**：视觉规范来自 项目根 `design.md`——AI 不在原型阶段做视觉创新（防漏服从、防迭代漂移）

---

> **步骤协议**：机械读取、内部消化、写文件和检查正常时静默执行，不逐步播报完成总结。只在 🚫 人类确认、会改变范围/取舍的 ⚖️ 默认判定、异常/`blocked` 和最终移交时输出；🚫 必须停下等明确回应，⚖️ 用一行结论 + 理由后继续，用户可随时推翻。

## 会话启动

**第一步：读上下文**：

```
Read: iterations/vN/prd.md
Read: design.md 的「全局视觉基线」+ 与本期功能同名的页面规格（若存在）；旧文件没有稳定页面标题时读取全文
```

**第二步：状态判断**：

| 观察到的状态 | 处理方式 |
|-------------|---------|
| `prototype.html` 不存在，`design-brief.md` 也不存在 | 从 Step 1 开始 |
| `design-brief.md` 存在，`prototype.html` 不存在 | 说"上次选了外部设计会话路径，简报已生成，等你把 prototype.html 带回来。带回后告诉我'设计稿已就位'"，然后挂起等待 |
| `prototype.html` 存在，但 `prototype-map.md` 不存在 | 读取 `prototype.html`，对照 PRD AC 生成 `prototype-map.md`，再从 Step 5 开始 |
| `prototype.html` + `prototype-map.md` 均存在、用户未确认 OK | 从 Step 5 开始（对抗审查 → 用户走查） |
| `prototype.html` 存在且用户已确认走查 OK | Step 7（收尾） |

**开场说**：

> 「本次任务是完成 v{N} 交互原型。我先核 PRD 是否已足够支撑交互设计，只补问缺失或矛盾点；随后自己消化并出可点击 HTML 让你走查。中间过程不需要你审场景文字或流程图。」

## Step 1：PRD 缺口补齐（含 design.md 视觉对接）

### Step 1.1：PRD 完整度扫描 + 缺口问答

**涵盖参考清单**（按需，不强制全覆盖）：

| 方面 | 例子 |
|------|------|
| 功能边界 | 这个功能负责什么、不负责什么 |
| 用户角色 | 谁会用、有几种角色 |
| 典型场景 | 用户主要从哪几条路径进入、做什么 |
| 业务约束 | 必须遵守的规则（删除前确认、金额上限、权限等） |
| 入口情况 | 从哪些页面 / 菜单进入 |
| 数据状态 | 初始 / 中间 / 最终态、空态 |
| 异常处理 | 可能出什么错、用户怎么知道 |

先逐项从 PRD 找入口、角色、典型场景、业务约束、初始/中间/终态、空态和异常反馈。全部明确且互不矛盾 → 不访谈、不复述 PRD，静默进入 Step 1.3。只有缺失、冲突或 PRD 明标「留 draft-ux 确认」的项才提问；每个问题必须点名缺口所在功能/AC，不重问已有答案。

### Step 1.2：缺口结论确认（条件触发）

仅 Step 1.1 实际问过问题时，输出**补充结论**，只列新补充或修正的事实：

```markdown
**draft-ux 补充结论 · v{N}**
- {功能/AC}：{补充或修正事实}
```

**不落盘**——临时对答手段。

🚫 等用户确认补充结论：
- OK → 转 Step 1.3
- 改 → 按修改继续聊，刷新总结再审
- 主动加方面 → 加上继续

### Step 1.3：design.md 全局基线 + 页面覆盖检查

分别检查：① 全局视觉基线是否完整；② 本期 `draft-ux: 需要` 的功能/页面在 `## 八、页面规格` 下是否已有稳定标题。全局完整但本期有新页面时，不重问全局基调，记录缺失页面标题，继续设计；这些页面在用户走查通过后由 Step 7 按已接受原型补入。

**全局基线为空或缺失时**：

AI 问 3–5 个视觉基调问题：

- 深色 / 浅色界面？
- 品牌主色（hex 或描述）？
- 字体偏向：正式 / 活泼？
- 圆角风格：硬朗 / 圆润？
- 控件密度：紧凑 / 宽松？

用户回答后，AI 写 项目根 `design.md` 初稿——填全局视觉基线（变量、标准控件样例）并为本期页面预留 `## 八、页面规格` 下的稳定标题。后续只属于某页的布局、控件组合和状态视觉写进该页，不重复 token。

**落盘**：项目根 `design.md`（特例：项目级跨迭代文件，落盘规则之外）。

🚫 等用户审 design.md 初稿，OK 后转 Step 2。

## Step 2：AI 内部消化（不外露）

**必走清单**：

| # | 内部动作 | 颗粒度 |
|---|---------|--------|
| 1 | 场景拆解 | "用户从 X → 操作 Y → 到 Z" 内部清单（命名 S1/S2/…） |
| 2 | AC→Sx 覆盖映射 | 对照 PRD 每条 AC：标注覆盖的 Sx（前端可视范围）或排除原因（纯数据层/后端）；无对应 Sx 的前端 AC 需补场景 |
| 3 | 流程穿线 | 连成路径，识别分叉/空态/错误，画 mermaid 内部草稿 |
| 4 | 画面构思 | **信息架构层为主**：承载方式（Drawer / 全页 / 内联）、区块组成（顶部信息卡 + 操作栏 + 列表） |
| 5 | 行为待决扫描 | 逐画面扫描，列内部清单（不外露）。扫描项：危险操作摩擦力（直接执行/确认弹窗/手动输入确认词）/ 批量操作选中触发（勾选框常驻/hover 出现/长按）/ 表单未保存离开（直接走/弹警告/自动存草稿）/ 空态 CTA 形态（纯文案/有引导按钮+指向何处）/ 权限受限时的 UI（隐藏按钮/禁用+tooltip/操作后报错）/ 操作成功后的页面行为（停留/跳回列表/刷新）/ 数据加载失败的处理（重试按钮/静默降级/整页错误态）/ 列表行点击行为（跳页/开侧抽屉/展开行内折叠）。**耦合兜底**：若某条行为决策依赖 PRD 中的数据策略（如软删/硬删）但 PRD 未明确，标为待确认，Step 3 追问补齐 |

**组件视觉细节留 Step 4 直接落**——Step 2 不预想；行为歧义项进入出口 X 判断。

**结束出口（两选一）**：

| 出口 | 触发 | AI 动作 |
|------|------|---------|
| **X** | 满足任一：① 结构性关键决策点（多种合理走法 + 影响下游多画面）② 行为待决清单非空（存在交互层歧义或 PRD 标注「留 draft-ux 确认」的待确认项） | 告知用户「我识别到几个关键决策需要先对一下」→ 转 Step 3 |
| **Y** | 行为待决清单为空且无结构性决策点 | 告知用户「业务理解和画面构思已就绪，准备出原型了，可以吗？」→ 用户认同 → 转 Step 3.5 |

🚫 出口 Y 等用户认同；出口 X 用户知悉后直接进 Step 3。

## Step 3：关键决策中间产物对答（按需触发）

**触发**：仅当 Step 2 出口 X。

**双轨机制**：

| 决策类型 | 默认方式 | 升级条件 |
|---------|---------|---------|
| 结构类（承载方式/组织粒度/多步流程等） | mini HTML 中间产物——不点不出感觉 | — |
| 行为类（来自 item 5 待决清单） | 文字问答，一问一答逐条过 | AI 判断该决策视觉依赖（效果无法用文字说清），主动出 mini HTML，不等用户请求 |

**典型决策示例**（防漏）：

| 决策 | 选项 |
|------|------|
| **[结构]** 表单承载方式 | Drawer / 全页跳转 / 居中弹窗 / 原地内联展开 |
| **[结构]** 列表组织粒度 | 一行一员工 / 一行一记录 / 分组折叠 |
| **[结构]** 多操作摆放 | 页面级 / 行级 / 工具栏 |
| **[结构]** 复杂数据呈现 | 卡片 / 表格 / 时间线 / 看板 |
| **[结构]** 多步流程编排 | 单页分区 / 分步向导 / Tab |
| **[行为]** 危险操作确认 | 直接执行 / 二次确认弹窗 / 手动输入确认词 |
| **[行为]** 批量选中触发 | 勾选框常驻 / hover 出现 / 长按触发 |
| **[行为]** 表单未保存离开 | 直接走 / 弹警告 / 自动存草稿 |
| **[行为]** 空态 CTA | 纯文案 / 有引导按钮（指向何处） |
| **[行为]** 权限受限 UI | 隐藏按钮 / 禁用+tooltip / 操作后报错 |
| **[行为]** 操作成功后行为 | 停留当前页 / 跳回列表 / 刷新 |
| **[行为]** 加载失败处理 | 重试按钮 / 静默降级 / 整页错误态 |
| **[行为]** 列表行点击 | 跳页 / 开侧抽屉 / 展开行内折叠 |

**结构类选项用 mini HTML 呈现，禁文字方案描述**（违红线 5）；行为类直接文字问答，视觉依赖时 AI 主动出 mini HTML。

每次给 2–3 个方案 → 用户选 / 改 → 反复直到定。跨迭代决策写 项目根 `decisions.md`，单期不落盘。全部对完 → 告知用户 → 转 Step 3.5。

🚫 用户认同处。

## Step 4：生成 HTML 原型

单文件 HTML，CSS/JS 内联；多画面 vanilla JS `display` 切换。产出 `iterations/vN/prototype.html`。

**覆盖要求（红线性质）**：

| # | 要求 |
|---|------|
| 1 | 流程图每条路径都能在原型中走通，无死锚点 |
| 2 | 每画面信息架构落实（承载方式 / 区块组成） |
| 3 | Step 3 关键决策结论已落实 |
| 4 | 视觉规范落实（项目根 `design.md` 变量，无硬编码颜色/字号/间距） |
| 5 | 状态可见性（hover / focus / disabled / 空态 / 错误态） |
| 6 | 占位数据符合业务场景（"张三 / 工号 10086 / 财务部"，不是"xxx / yyy"） |

**动效可选**（Drawer 滑入等）；成本高则跳过，无动效不是缺陷。

**AI 自检（写完后逻辑核查）**：

- 锚点连接性：每个 `href="#xxx"` 都能找到目标
- 路径覆盖：流程图每条路径都有对应 HTML 节点
- 状态可见性：每画面 hover/disabled/空态有对应 CSS 类
- 视觉规范遵守：grep `style=` 看有无硬编码颜色/字号

**不假装"浏览器打开"**——预检确认浏览器场景能力可用时必须实际打开并留证；不可用时只做逻辑核查，并把实机走查明确移交 Step 6。

**生成后：写 `prototype-map.md`**

生成 `iterations/vN/prototype-map.md`（Step 5 隔离审查的核查基线，AI 刚写完原型此时最准）：

````markdown
## 前端 AC 覆盖

| AC | 场景 | HTML 锚点 |
|----|------|---------|
| {AC-nn} | {Sx[, Sy]} | `#{id}[, #{id}]` |

## 排除 AC

| AC | 排除原因 |
|----|---------|
| {AC-nn} | {后端/数据层/cron 等，无前端 UI} |
````

转 Step 5。

## Step 5：独立对抗审查

启动全新隔离审查单元（纯审查/一致性核对；能力档位与具体模型见运行时映射），读 `templates/review-briefs/prototype-review.md`（含自读指令），告知本期版本 vN，由审查单元自读 `prototype-map.md` + `prototype.html`，输出 findings 与未完成验证。若当前运行时无法提供独立上下文，标记 `blocked`，不得由同一执行会话自审替代。

**结果处理**：

- 无阻断且验证完成 → 转 Step 6（用户走查），建议随原型交付
- 有阻断或必要验证未完成 → 展示缺口给用户，🚫 用户决策：
  - 修复缺口 → AI 改原型 / 回外部设计会话补做 → 重跑 Step 5
  - 明确豁免（注明原因）→ 记录后转 Step 6

## Step 6：用户走查 + 反馈调整

**AI 交付话术**：

> 「原型 `iterations/vN/prototype.html` 已就绪，请在浏览器打开走查。沿业务路径点一遍，顺便看交互体感和视觉。有任何问题直接说。」

**反馈调整循环**：

- 用户提反馈 → AI 逐条判：**改原型** / **记待办** / **认为属过度**
- 改完 → 让用户再走查
- 待办项 → 落到项目级 `backlog.md`（已有架构）
- 反复直到用户满意

**走查结束标志**：**用户主动说"OK 可以了"** → 转 Step 7。**不设 AI 主动判定**——是否结束由客户说了算。

🚫 用户"OK"处。

## Step 7：收尾移交

先依据用户已确认的 prototype，为 Step 1.3 记录的缺失页面在 `design.md ## 八、页面规格` 补稳定 `### {页面/功能名}`：只写该页布局、区块、控件组合、空态/错误态视觉与响应式例外，不复制全局 token。已有页面若本期经用户确认发生变化则原地更新。用户刚完成原型走查即构成页面规格确认，不再新增一轮重复问答。

写 `ux-flows.md`（从内部消化提炼），仅两段：

````markdown
# UX Flows · v{N}

## 场景列表

### 功能：{功能名}
- S1：用户从 {入口}，执行 {操作}，到达 {去向}。
- S2：……

### 功能：{功能名}
- S3：……

## 流程图

```mermaid
flowchart TD
    ……
```
````

**完成判据自核**：

- prototype.html 在浏览器可走通全路径 ✓
- design.md 已存在并被原型实际使用（无硬编码颜色/字号） ✓
- 用户已确认走查 OK ✓
- 跨迭代影响的关键决策已写入 项目根 `decisions.md`（如有） ✓

**git commit**：

```bash
git add iterations/vN/ux-flows.md iterations/vN/prototype.html iterations/vN/prototype-map.md
# design.md 若本期新增/更新页面规格则一并 add；无变化不重复提交
git commit -m "feat(ux): v{N} 交互流程图 + 原型 [{项目名}]"
```

**输出**：

```
✅ draft-ux v{N} 完成：{功能数} 个功能，{场景数} 条场景，{路径数} 条流程路径；原型落实 design.md 视觉规范，全路径已用户走查确认。
```

**移交话术**：

> 「交互原型完成，下一步 `draft-tech-design`。TRD 接口设计时请参考 `ux-flows.md` 流程图和 `prototype.html` 确认前端数据需求与画面字段。」

## 边界场景

| 场景 | 处理方式 |
|------|---------|
| PRD 某功能描述过于模糊，无法在 Step 1 问清 | 阻断，列出具体问题，要求用户回 `draft-prd-vN` 先明确该功能再继续 |
| 流程图分支极多，mermaid 渲染混乱 | Step 7 落盘时拆为多张子图（按功能分），分别在 `ux-flows.md` 中呈现 |
| 用户在 Step 6 走查中提出原型外的视觉创新建议 | 红线 6 禁视觉创新——指引用户改 项目根 `design.md` 后再落到原型 |
| 用户认为某条场景不需要原型覆盖 | 在 Step 7 落盘的场景列表中标注"[跳过原型]"并注明原因，流程图中保留该路径 |
| 走查中发现 PRD 有逻辑矛盾 | 暂停，列出矛盾点，询问用户决策，不擅自取舍 |
| 用户希望直接看场景列表 / 流程图（违背新姿态） | 解释新姿态——这些是 AI 内部工作；如确实需要可在 Step 7 落盘后查看，但生成阶段不外露 |
| 外部设计会话产出的 `prototype.html` 带回后路径断裂或死锚点多 | 告知用户具体问题（例："S3 路径的返回按钮无目标"），让用户回原设计会话修复后再带回；主线不自行修该会话产出的原型（避免两份来源混乱） |

## 隔离单元使用

**Step 5 独立对抗审查**：启动全新隔离审查单元，按运行时映射选择普通审查档，读 `templates/review-briefs/prototype-review.md`；审查单元自读 `prototype-map.md` + `prototype.html`，不收主线上下文。审查维度改动去改 brief 文件（单一来源）。

其余步骤（缺口问答、内部消化、决策对答、原型生成、走查）均为主线工作或对话推进，不使用隔离单元。
