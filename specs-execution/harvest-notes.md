# exec: harvest-notes

> CC 加载本文时，当前任务是收割成员个人积累仓、上提到 hact-method 公共层。在 **hact-method 工作区**执行（管理者心态）。
> 触发：管理者按需或周期性跑（如月末、或"多名成员都攒了一批待上提"时）。非每次 wrap-up 自动触发。

**上下文密度**：低。逐成员读 notes.md（小文件）+ 写公共层，不加载项目代码。

---

## 红线

- **只读成员仓**：对成员 notes 仓只 fetch/读，**绝不写、绝不回写**。上提进度只记在 hact-method 侧的收割游标。
- **尊重 `[心得]`**：`[心得]` 条目是成员私有，永不收割、永不上提。
- **不绕过去重**：写公共层前必须对照已有内容去重，避免规范文件冗余膨胀。
- **master 严格**：push 前向管理者报告；冲突必人工处理，不强推。

## 第一步：逐成员只读收割

对每个成员依次：

```bash
# 同步该成员 notes 仓（只读）。本地已存在则 fetch+pull；不存在则按登记地址 clone
git -C "{本地路径}" fetch origin 2>/dev/null && git -C "{本地路径}" pull 2>/dev/null \
  || git clone {仓地址} "{本地路径}"
```

读 `{本地路径}/notes.md`，**只取游标之后新增**的条目（用 `git -C "{本地路径}" log --oneline {上次收割commit}..HEAD -- notes.md` 辅助定位，或按条目日期）。

按标签分拣：`[规范]` / `[checklist]` / `[方法论]` 入收割篮；`[心得]` 跳过。

某成员仓不可访问 / 无新增 → 记录"跳过 {成员}"，游标不动，继续下一个。

```
✅ 逐成员收割完成：{成功 X 名 / 跳过 Y 名}，收割 [规范]{a} / [checklist]{b} / [方法论]{c} 条
→ 下一步：去重择优
```

---

## 第二步：去重择优

对收割篮逐条，对照公共层现有内容（`templates/standards/*`、`templates/checklists/*`、`方法论待议.md`）判断：

| 情况 | 处理 |
|---|---|
| 与公共层重复 | 丢弃 |
| 多人提同一问题 | 合并为一条，取最完整措辞 |
| 单人、通用、有价值 | 采纳 |
| 单人、仅个人/单项目相关、不通用 | 不上提，游标备注"已阅未采" |

```
✅ 去重择优完成：采纳 {M} 条 / 合并 {K} 组 / 丢弃 {X} 条
→ 下一步：写入公共层
```

🚫 采纳清单较多时，先让管理者过目采纳清单再写入

---

## 第三步：写入公共层

| 来源标签 | 目的地 | 操作 |
|---|---|---|
| `[规范]` | `templates/standards/{backend\|frontend\|shared}.md`（按内容归层；跨层条目写入独立的 `shared.md`） | 追加条目 |
| `[checklist]` | `templates/checklists/{backend\|frontend}-checklist.md` | 追加至对应分类 `[ ]` |
| `[方法论]` | `_meta/plans/方法论待议.md` | 追加 `- [ ] {日期} \| {问题} \| 来源：{成员} notes harvest` |

```
✅ 写入公共层完成：standards +{a} / checklists +{b} / 待议 +{c}
→ 下一步：推进游标
```

---

## 第四步：推进游标 + 提交

更新 `_meta/hact-config.md` 收割游标表：每成员记本次收割到的 commit / 时间戳 + 采纳条目数。

```bash
git add templates/standards/ templates/checklists/ _meta/plans/方法论待议.md _meta/hact-config.md
git commit -m "chore: harvest-notes 收割上提（{日期}）"
```

```
✅ harvest-notes 完成：上提 standards {a} / checklist {b} / 待议 {c}，游标已推进。
方法论类条目已进待议清单，可在后续方法论调整会话处理。
要 push 到 master 吗？
```

🚫 等管理者确认再 push（master 红线）
