## 第一层：架构轮廓

### Step 1：V0 准入 + 跨切面架构轮廓

先逐行做 V0 准入。只有同时满足以下条件的行才进入本轮：已证明被多个功能共同经过；约束稳定；晚建会横切多层/多模块、迁移数据或扩大安全风险；能由一根最薄真实切片或独立反例证明。其余行标 `V1+（理由）`，不为表格完整度预建。

若没有任何行通过门槛，停止创建 V0，只移除本会话新建且未提交的 `iterations/v0/` 脚手架；目录此前已存在或含其他内容则不删，报告后移交 V1 `draft-prd-vN`。若估量超过一个正常中型 develop 任务，先删到最难后补的约束；仍超出则同样改走 V1。

只对通过准入的 V0 行，结合已定栈各写一行「关注点 / 具体形式 / 承载位置 / 为什么晚建代价高」。不得为了凑后端、数据层、前端三层而补项。

🚫 等用户一次确认 V0 范围、架构轮廓与主要强制档；不再逐项重复确认

## 第二层：落实地基 + 走骨架设计

### Step 2：填 foundation.md「实际形式·档」+ 强制边诊断（核心）

先读 `templates/review-briefs/review-scope.md`：强制边只承诺正常开发误用与实际外部边界的防护，不把防开发人员恶意/有意绕过写进设计要求。

回填 `foundation.md`「二」表的「阶段 / 实际形式·档」列：V0 行写 `V0：{具体形式}（{档级}）`；其余写 `V1+：{推迟理由}`。只对 V0 行逐项对照「应有档」：

- 实际档 ≥ 应有档 → 通过。
- ⚠️ **安全敏感项（数据隔离 / 鉴权 / 越权）实际档未到构造级 → 不通过**：重选形式（如把"手写 where"改成"作用域 base repo 焊死"），到构造级为止；确实无法构造级 → 列疑点向用户明示风险，不静默放过。
- 命门自检：对每个 V0 行问"**一个图省事的人在这顺手写，会合规吗？**"——答否说明形式没顶到位。
- 「V1 马上要用」「以后也许会用」不能把 V1+ 行升级为 V0；只有晚建代价本身满足准入门槛才可升级。

原地更新项目根 `foundation.md`（活文档），不另存副本。

Step 1 已确认的范围不再另设等待点；若安全项无法达到构造级，才停下明示风险并请用户裁决。

---

### Step 3：写走骨架设计 `iterations/v0/foundation-design.md`

把 Step 1 架构 + 各块契约落成可供 develop 建造的设计（**薄**——地基件多是已知样板，重点在契约与连接，不堆细节）：

```markdown
## 走骨架设计 · v0

### 一、地基件清单（develop 要建的承重墙）
只列获准进入 V0 的件：名称 / 形式 / 关键契约（如作用域 repo 方法签名）。不得把 V1 专用运行器、黄金样本、基线、完整业务模块列为“额外交付”。

### 二、贯穿作用域的构造级落地
{作用域 base repo 怎么让"不带作用域就查不了"——数据隔离构造级的具体机制}

### 三、标杆穿透切片
选一根**最小真实业务切片**（取自 foundation「一」核心实体的最简单一个），从项目的真实主入口走到持久化或外部边界，证明获准地基件能连接；Web 项目可为前端→API→DB，但不为凑全栈另建不存在的层。
- 切片：{选哪个实体的什么最小操作}
- 端到端路径：{真实主入口 → 本轮获准地基件 → 持久化或外部边界}
- **它同时是标杆模块**：按范本质量建，develop 末端登记进 reusables.md 供后续照抄。
```

> **纪律：只立最难后补的承重墙、不装修。** 一根穿透切片证明架构即可；切片之外的业务准备全部回 V1，不设“V0 额外交付”。

## 红线

- **禁止产代码**：本步只出设计文档；瓶颈管道 / base repo / 主题框架等公共代码归 V0 `develop(source=foundation)`。
- **禁止安全项停在弱边**：数据隔离 / 鉴权 / 越权的实际档未到构造级，不签 G2（重选形式或列疑点）。
- **禁止厚走骨架**：只立最难后补的承重墙、一根穿透切片证明架构，不建投机完整框架。
- **禁止 V1 前置仓**：运行器、黄金样本、基线、业务脚手架若只是后续功能要用，归 V1，不得列作 V0 额外交付。
- **禁止全表驱动**：预置关注点是候选清单；V1+ 行不实现、不审查、不阻断 G2(v0)。
