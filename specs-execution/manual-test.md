# exec: manual-test

> CC 加载本文时，当前任务是提供测试环境、引导用户自主验收、派修复任务、用户通过后签 G4。
> 本 task 以用户为主导，AI 不替用户判断通过与否。

**上下文密度**：低（等待用户交互为主）。不全量加载代码，只读 PRD 和联调测试结果。

---

## 步骤追踪协议

每步完成后输出：
```
✅ [步骤名] 完成：[2–3 句结论]
→ 下一步：[步骤名] — [一句说明]
继续？
```
🚫 标记处必须等用户明确回应后才继续。

---

## 会话启动

读以下文件（精确加载）：
- `iterations/vN/prd.md`（acceptance criteria 段落）
- `integration-tests/result-{最新日期}.md`（联调结论）

---

## Step 1：确认测试环境

确认以下三项可访问：
- 后端服务可达（健康检查端点返回正常）
- 数据库指向测试库（不是生产库）
- 前端页面可打开

**环境不完备时**：逐步引导用户建立（参照 `standards-shared.md` 测试环境约定），就绪后继续。

```
✅ 测试环境确认：{服务地址} 可访问，数据库为测试库。
→ 下一步：告知用户验收信息
继续？
```

---

## Step 2：告知用户验收信息

向用户说明：

```
测试环境：{地址}

本期功能范围（来自 PRD）：
- {AC 1}
- {AC 2}
...

联调测试结论：{N} 个场景全通过 / 有 {X} 个 [不阻断] 问题已记入 backlog。

请自主探索验收，发现问题随时告知。
```

🚫 等用户反馈（不催促，不预设结论）

---

## Step 3：收集反馈 + 派修复任务

用户每反馈一个问题：
1. 记录现象 + 复现步骤（不替用户判断严重性）
2. 写 develop 任务包（`source=manual-test`，urgency 按用户描述严重性填），写入 `queue/{task-id}.md`
3. 同时追加到 `iterations/vN/acceptance-report.md`（见"产物格式"）

每派完一批修复任务：
```
已将以下问题派发修复：
- {task-id}：{问题描述}
...
修复完成后我会通知你复测。
```

---

## Step 4：等待复测

develop(source=manual-test) 全部 [merged] 后，通知用户：
```
修复任务已全部合并，请复测：{具体修复了哪些问题}。
```

🚫 等用户复测反馈

重复 Step 3–4，直到用户明确说「验收通过」。

---

## Step 5：写验收报告 + 签 G4

用户明确通过后：

**写验收报告** (`iterations/vN/acceptance-report.md`)：

```markdown
# 验收报告 · vN · {项目名}

## 验收结论
通过

## 问题记录
| # | 现象 | 复现步骤 | 状态 |
|---|------|---------|------|
| 1 | {描述} | {步骤} | 已修复 / 记入 backlog |

## 验收通过日期
{YYYY-MM-DD}
```

**询问签 G4**：
```
验收已通过，要签 G4 吗？
```

🚫 等用户确认

用户确认后：在 `iterations/vN/gates.md` 写入 G4，commit。

```
✅ manual-test 完成：G4 已签，验收通过。
→ 下一步：deploy（部署）或 wrap-up-iteration（收尾，可并行）
```

---

## 上下文管理

**等待期间断点续做**（用户长时间不回复后重新开会话）：
1. 读 `iterations/vN/acceptance-report.md` 确认当前问题状态
2. 读 `queue/` 找 source=manual-test 的任务包，确认 [merged] / [可取] / [taken-by] 状态
3. 从上次停在的步骤继续，不重复已完成的操作

**边界**：
- 用户反馈超出本期 PRD 范围 → 告知「该问题不在本期范围」，记入 backlog，不派修复
- 用户反馈问题 G4 签字前改变结论 → 继续处理；G4 已签后提新问题 → 走下期 B 类 `dispatch-new`
