# task: draft-ux

**discipline**: `product`
**Gate**: 无（可选前置于 G2，由执行人决定是否触发）
**属性**: `version`

> 从 PRD 功能出发，枚举用户视角的业务流，绘制流程图，输出可交互 HTML 原型，在 TRD 开始前确认交互逻辑。

---

## 前置条件

- **触发**：本期功能含新页面 / 新核心交互流程 / 用户路径较复杂；由执行人判断是否需要
- **上游**：`draft-prd-vN` 已完成，G1 已签
- **可选性**：纯数据管理类页面（标准增删改查、无分支流程）可跳过，直接进 `draft-tech-design`
- **不可替代**：不能以 PRD 中的 acceptance criteria 替代本 task——PRD 描述功能边界，本 task 描述用户如何穿越功能

---

## 字段规范

| 字段 | 类型 | 必填 | 取值 / 说明 |
|------|------|:----:|------------|
| `version` | string | ✅ | 与本期 PRD / TRD 版本号一致，如 `v1` |

---

## 主要产物

| 产物 | 路径 | 格式 |
|------|------|------|
| 场景枚举 + 流程图 | `iterations/vN/ux-flows.md` | Markdown，含场景列表 + mermaid 流程图 |
| HTML 原型 | `iterations/vN/prototype.html` | 自包含单文件，可在浏览器直接打开 |

**ux-flows.md 必含内容：**

| 段落 | 说明 |
|------|------|
| 场景列表 | 每条一句话："用户从 X 进入，执行 Y，到达 Z" |
| 流程图 | mermaid flowchart，覆盖全部场景及分支 |
| 死路检查 | 确认每条分支都有明确出口 |

**prototype.html 要求：**

| 要求 | 说明 |
|------|------|
| 自包含 | 单个 HTML 文件，无外部依赖 |
| 可点击 | 每个操作点击后跳转到对应下一状态 |
| 全覆盖 | 流程图中每条路径都可完整走通 |
| 轻量 | 不需要精美，不需要真实数据，需要路径可达 |

---

## 完成判据

- [ ] PRD 中每个功能都有对应场景（无遗漏功能）
- [ ] 每个场景都有入口、操作、出口三要素
- [ ] 流程图中无死路（每条分支都有明确去向）
- [ ] prototype.html 可在浏览器打开，无 JS 报错
- [ ] 流程图中每条路径都能在原型中走通，不卡死
- [ ] 用户已确认场景列表完整、原型逻辑正确

---

## 接口约定

**输入来自**

| 上游 | 交接内容 | 格式 |
|------|---------|------|
| `draft-prd-vN` | 定稿 PRD，含功能清单和 acceptance criteria | `iterations/vN/prd.md` |

|-----------|---------|------|
| `draft-tech-design` | 已确认的交互流程 + 原型，作为接口设计的业务依据 | `iterations/vN/ux-flows.md` + `iterations/vN/prototype.html` |
