# task: draft-ux

**discipline**: `product`
**Gate**: 无（可选前置于 G2，由执行人决定是否触发）
**属性**: `version`

> 从 PRD 功能出发，CC 当交互工程师消化业务，输出可交互 HTML 原型，在 TRD 开始前确认交互逻辑。

---

## 前置条件

- **触发**：本期功能含新页面 / 新核心交互流程；由执行人判断是否需要
- **上游**：`draft-prd-vN` 已完成，G1 已签
- **可选性**：纯数据管理类页面（标准增删改查、无分支流程）可跳过，直接进 `draft-tech-design`
- **不可替代**：不能以 PRD 中的 acceptance criteria 替代本 task——PRD 描述功能边界，本 task 描述用户如何穿越功能

---

## 角色姿态

**CC = 交互工程师；用户 = 客户。** 客户只参与上游业务沟通 + 下游设计稿走查，中间过程内部消化、不外露。用户不审场景文字、不审流程图拓扑、不审线框图——这些是 CC 的内部工作。

---

## 字段规范

| 字段 | 类型 | 必填 | 取值 / 说明 |
|------|------|:----:|------------|
| `version` | string | ✅ | 与本期 PRD / TRD 版本号一致，如 `v1` |

---

## 主要产物

| 产物 | 路径 | 格式 |
|------|------|------|
| 场景列表 + 流程图 | `iterations/vN/ux-flows.md` | Markdown，**仅含两段**：场景列表 + mermaid 流程图 |
| HTML 原型 | `iterations/vN/prototype.html` | 自包含单文件，可在浏览器直接打开 |
| 设计简报 | `iterations/vN/design-brief.md` | 含 AC 覆盖范围声明；Claude Design 路径必有，CC 路径亦应落盘 |
| 视觉规范（如首次） | `design.md` | 项目级跨迭代文件；首次 draft-ux 时由本 task 生成初稿 |

**ux-flows.md 必含内容（仅两段）**：

| 段落 | 说明 |
|------|------|
| 场景列表 | 每条一句话："用户从 X 进入，执行 Y，到达 Z"；按功能分组、命名场景（S1/S2…）供 TRD 在 API 注释里锚定 |
| 流程图 | mermaid flowchart，覆盖全部场景及分支，无死路 |

> 旧版 ux-flows.md 含「死路检查 / 交互决策 / 交互质量走查记录」三段，本轮重构已移除——前两段并入 CC 内部消化与 Step 3 决策对答，走查记录因 subagent 冷审去除而无产物。

**prototype.html 要求**：

| 要求 | 说明 |
|------|------|
| 自包含 | 单 HTML 文件，CSS/JS 内联，无外部依赖 |
| 可点击 | 每个操作点击后跳转到对应下一状态 |
| 全覆盖 | 流程图中每条路径都可完整走通 |
| 落实 design.md | 视觉规范来自 `design.md`——字体/字号/色彩/间距/控件样式无硬编码 |
| 状态可见性 | 每画面 hover / focus / disabled / 空态 / 错误态可见 |

---

## 完成判据

- [ ] PRD 中每个功能都有对应场景（无遗漏功能）
- [ ] 每个场景都有入口、操作、出口三要素
- [ ] 流程图中无死路（每条分支都有明确去向）
- [ ] prototype.html 可在浏览器打开，无 JS 报错
- [ ] 流程图中每条路径都能在原型中走通，不卡死、无死锚点
- [ ] 原型落实 `design.md` 视觉规范（无硬编码颜色/字号/间距）
- [ ] 原型状态可见性落实（hover/focus/disabled/空态/错误态）
- [ ] 跨迭代影响的关键决策已写入项目级 `decisions.md`（如有）
- [ ] design-brief.md 已落盘，含 AC 覆盖范围声明
- [ ] 独立对抗审查通过（声明覆盖的前端 AC 均有对应原型路径，或缺口已明确豁免）
- [ ] 用户已实际走查原型并确认逻辑与体验正确
