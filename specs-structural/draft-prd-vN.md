# task: draft-prd-vN

**discipline**: `product`
**Gate**: G1（可选签于任务尾部）
**属性**: `version`

> 捕获本期用户故事和 acceptance criteria，输出 PRD，签 G1。

---

## 前置条件

- **触发**：A 类需求到来，项目已初始化（`` 目录存在）
- **迭代项目**：读取 `project.md` 了解已有产品现状，不重复已有内容
- **无 Gate 前置**：draft-prd-vN 是流程起点，无上游 Gate 要求
- **B 类任务**（需求已明确的 bug / 优化）：跳过本 task，直接走 `dispatch-new`

---

## 字段规范

| 字段 | 类型 | 必填 | 取值 / 说明 |
|------|------|:----:|------------|
| `version` | string | ✅ | `v1` / `v2` / …；与本期 TRD、sprint 文件版本号一致 |

---

## 工作内容

1. **场景还原**：用「谁 / 情境 / 问题 / 现有解法 / 不足」格式还原需求背景；不符合格式则继续追问，不跳过
2. **发散 + 筛选**：列出 3–5 个可能解法，用三角（D 用户价值 / F 技术可行性 / V 业务价值）逐个评估，确定要做的功能范围
3. **确认 MVP 边界**：与用户对齐"不做什么"及原因，记录排除项
4. **输出 PRD 草稿**：包含以下 6 个段落（见"主要产物"中的结构说明）
5. **解决开放问题**：PRD 中列出的开放问题逐条与用户确认，全部解决后定稿
6. **询问签 G1**：「PRD 已完成，要签 G1 吗？」——用户确认后 commit，G1 签字写入 `iterations/vN/gates.md`

---

## 主要产物

| 产物 | 路径 | 格式 |
|------|------|------|
| PRD | `iterations/vN/prd.md` | Markdown，含 6 个固定段落 |
| project.md 更新（产品层） | `project.md` | 追加或更新产品层内容 |

**PRD 必含段落：**

| 段落 | 说明 |
|------|------|
| 产品目标 | 一句话，聚焦本期价值主张 |
| 目标用户 | 画像 + 核心痛点（对应三角 D） |
| 核心功能 | 每个功能：场景描述 + acceptance criteria + 明确排除项 |
| 用户故事 | 3–5 个，覆盖核心场景 |
| MVP 边界 | 明确"不做什么"及原因 |
| 开放问题 | 定稿前需解决的问题列表；定稿时应为空 |

---

## 完成判据

- [ ] 场景还原完整（5 要素齐全）
- [ ] 三角评估已逐功能完成
- [ ] PRD 6 个段落全部存在，无空段
- [ ] "开放问题"段落为空（全部已解决）
- [ ] 有新页面 / 新交互 / ≥3 个状态：已在 acceptance criteria 中覆盖交互规格
- [ ] project.md 产品层已更新
- [ ] G1 已签（`gates.md` 已记录 + commit）

## 接口约定

**输入来自**

| 上游 | 交接内容 | 格式 |
|------|---------|------|
| 用户（需求方） | 需求描述（口头 / 文字） | 对话 |
| `init-project` | 项目目录结构就位 | `` |

**输出给**

| 下游 task | 交接内容 | 格式 |
|-----------|---------|------|
| `draft-tech-design` | 定稿 PRD + G1 已签 | `iterations/vN/prd.md` |
| `revise-doc`（如有修订） | PRD 被标记为待修订 | backlog `[修订]` 条目 |

---

## 边界场景

| 场景 | 处理方式 |
|------|---------|
| 需求方反复改需求，场景还原始终不稳定 | 优先澄清新概念，不在旧方案上打补丁；超过 3 轮仍不稳定则上报 |
| 首期项目 | 必须输出完整视觉规格到 `project.md`（色彩 / 字体 / 间距关键词） |
| 迭代项目（已有 PRD） | 只写本期增量，引用已有 project.md，不重写全量 |
| 功能范围过大（用户故事 > 6 个） | 主动建议拆期，给出优先级排序，等用户决策后再写 PRD |
| B 类需求在对话中升级为 A 类（涉及新用户场景） | 停止 B 类流程，通知用户走 A 类，重新建 draft-prd-vN task |

---

## 异常处理

| 情况 | 处理方式 |
|------|---------|
| 用户不认可三角筛选结论 | 重新过一遍，不强行推进；若循环超过 3 次，记录分歧点上报 |
| PRD 定稿后发现遗漏关键功能 | 创建 `revise-doc(target=prd)` task，不直接修改已签 G1 的 PRD |
| 用户明确要求跳过某个段落 | 在对应段落注明"用户决定跳过：{原因}"，不留空 |
