# task: harvest-notes

**discipline**: `management`
**Gate**: —
**属性**: 无

> 收割成员个人积累仓（hact-notes），把验证有效的 `[规范]`/`[checklist]`/`[方法论]` 条目去重择优，上提到 hact-method 公共层。pull 模型：管理者拉取，开发者不推送。

---

## 前置条件

- **Gate**：无
- **执行工作区**：hact-method（方法论心态）——要写公共层，须管理者权限
- **依赖**：`_meta/hact-config.md` 的「成员个人积累仓登记表」非空
- **权限**：对成员 notes 仓**只读**；对 hact-method 公共层可写
- **文件**：
  - `_meta/hact-config.md`（成员仓登记表 + 收割游标）
  - 各成员本地仓 `E:\group-code\hact-notes-{name}\notes.md`（只读）

---

## 字段规范

无特殊字段。可选记录本次收割的批次标识（日期），写入游标表备注。

---

## 工作内容

### 第一步：确定收割范围

读 `_meta/hact-config.md`：
- 「成员仓登记表」→ 得到要遍历的成员清单 + 各自 notes 仓地址 / 本地路径
- 「收割游标」→ 得到每个成员"上次收割点"（commit / 时间戳）

### 第二步：逐成员只读收割

对每个登记成员：
1. 同步其 notes 仓（`git fetch` + 只读 pull；本地不存在则按登记地址 clone 到只读位置）
2. 读 `notes.md`，**只取游标之后新增**的条目
3. 按标签筛选：`[规范]` / `[checklist]` / `[方法论]` 纳入收割；`[心得]` **跳过**（私有，永不上提）

### 第三步：去重择优

对收割到的条目，对照公共层现有内容判断：

| 情况 | 处理 |
|---|---|
| 与公共层已有条目重复 | 丢弃（不重复上提） |
| 同一问题多名成员都提 | 合并为一条，措辞取最完整的 |
| 单人提出、表述通用、有价值 | 采纳 |
| 单人提出、仅个人/单项目相关、不通用 | 不上提（可在游标备注标注"已阅未采"，避免下次重看） |

### 第四步：写入公共层

| 来源标签 | 目的地 |
|---|---|
| `[规范]` | `templates/standards/{backend\|frontend}.md`（按内容归层；跨层归 shared 段或两份都补） |
| `[checklist]` | `templates/checklists/{backend\|frontend}-checklist.md` |
| `[方法论]` | `_meta/plans/方法论待议.md`（格式：`- [ ] {日期} | {问题} | 来源：{成员} notes harvest`） |

### 第五步：推进游标

更新 `_meta/hact-config.md` 收割游标表：每个成员记录本次收割到的 commit / 时间戳 + 本次采纳条目数。**不回写成员仓**。

### 提交

收割完成后 commit + push hact-method（管理者权限）。

## 边界场景

| 场景 | 处理方式 |
|------|---------|
| 某成员 notes 仓不可访问（无权限 / 仓不存在 / 网络） | 记录"本轮跳过 {成员}"，不阻断其他成员收割，游标不动 |
| 某成员自上次收割无新增 | 跳过，游标不动 |
| 成员把本该上提的内容误标 `[心得]` | 不收割（尊重私有标记）；可在收割小结提示成员自查 |
| 同一条规范与上期 standards 已重复 | 丢弃，不重复写入（与 draft-tech-design 双源去重逻辑呼应） |
| 登记表为空 | 输出"无登记成员，无可收割"，任务空跑结束 |

---

## 异常处理

| 情况 | 处理方式 |
|------|---------|
| 收割中途某成员仓 fetch 失败 | 跳过该成员（游标不推进），继续其余；小结里列出失败成员供重试 |
| 采纳条目归层有歧义（前端？后端？shared？） | 归 `shared` 或两份都补；拿不准的降级为 `[方法论]` 待议，留人工定 |
| push hact-method 冲突 | 停止，先 pull 解决冲突再 push（master 严格，冲突必人工处理） |
