# task: manual-test

**discipline**: `product`
**Gate**: G4（可选签于任务尾部）
**属性**: 无

> 提供测试环境，由用户主导验收，收集反馈派修复任务，用户明确通过后签 G4。

---

## 前置条件

- **触发**：`generate-integration-tests` 三条件全部满足（联调清单全有结论 / 主流程无阻断 / backlog 已分级）
- **文件**：
  - `iterations/vN/prd.md`（acceptance criteria，验收基准）
  - `integration-tests/result-{日期}.md`（联调结果，用于向用户说明当前状态）

---

## 字段规范

本 task 无特有属性字段。

---

## 工作内容

1. **确认测试环境**：确认测试环境可访问（服务可达 / 数据库指向测试库 / 前端可打开）；环境不完备时，指导用户逐步建立（参照 `standards-shared.md` 测试环境约定段落），环境就绪后再继续
2. **告知用户**：说明测试环境地址 + 当前功能范围（引用 PRD acceptance criteria）；不引导用户按特定路径操作，由用户自主探索
2. **收集反馈**：用户反馈问题时，记录现象 + 复现步骤；不替用户判断问题严重性
3. **派修复任务**：将反馈问题写成 develop 任务包（source=manual-test），入 queue；告知用户「已派发修复，完成后请复测」
4. **等待复测**：develop(source=manual-test) 全部 [merged] 后，通知用户复测；不催促，不预判结论
5. **循环直至通过**：重复步骤 2–4，直到用户明确说「验收通过」
6. **询问签 G4**：「验收已通过，要签 G4 吗？」——用户确认后 commit，G4 写入 `iterations/vN/gates.md`

## 边界场景

| 场景 | 处理方式 |
|------|---------|
| 用户长时间不回复（验收搁置） | 不催促；在 progress.md 记录等待状态，下次会话接续 |
| 用户反馈的问题超出本期 PRD 范围 | 告知用户该问题不在本期范围内，记入 backlog 留下期处理；不派修复任务 |
| 用户反馈无法复现 | 在验收报告记录「用户反馈，无法复现」，标 `[待观察]`，不阻断验收通过 |
| 验收中发现根因在 PRD 定义歧义 | 创建 `revise-doc(target=prd)`，明确定义后再复测 |
| 用户要求加入新功能才算通过 | 属于需求变更，不在本期验收范围；建议下期走 `draft-prd-vN` |

---

## 异常处理

| 情况 | 处理方式 |
|------|---------|
| 同一问题修复后反复出现 | 超过 2 次，上报；判断是否根因在设计层，若是则创建 `revise-doc` |
| 测试环境与生产环境行为不一致 | 在验收报告中注明差异，由用户决定是否接受或需要在生产环境复验 |
| 用户验收后改变结论（通过后又提新问题） | 若在 G4 签字前：继续处理；若已签 G4：走下期 B 类 `dispatch-new` |
