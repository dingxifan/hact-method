# 05 — 个人积累仓管理（管理者操作手册）

> 面向**管理者**（有 `management` 授权、且是团队 Gitee 组织 owner/admin 的人）。
> 讲清"**在什么节点、如何**为成员创建个人积累仓 `hact-notes-{name}`"，以及与登记、收割的衔接。
>
> **核心前提**：个人仓**跟人、不跟项目**——一个人**只建一次**。之后他参与新项目，只需确认已登记，**不重复建**。
> 判据极简：**`_meta/hact-config.md` 成员登记表里没有这个人 = 没建过 = 要建；有 = 跳过。**

---

## 一次性前置（整个团队配一次）

| 项 | 说明 |
|---|---|
| 团队 Gitee 组织 | 所有 `hact-notes-*` 仓都建在这个组织下。组织名记入 `_meta/hact-config.md` 的 `notes-org`。管理者须是该组织 **owner/admin**——这样他对所有 notes 仓**天然只读**，正好用于 `harvest-notes` 收割，无需逐仓授权 |
| Gitee Token | 管理者的 Personal Access Token，需对 `{notes-org}` 有**建仓 + 管理协作者**权限。仅操作时临时使用，不写入任何文件 |
| 登记位置 | `_meta/hact-config.md` 的「成员个人积累仓登记表」+「harvest-notes 收割游标」两张表 |

---

## 在什么节点做（节点总览）

| 节点 | 触发时机 | 做什么 |
|---|---|---|
| **A · 立项时** | 跑 `init-project`，到 Step 4.5 | 为该项目**全部成员**（含发起人自己）逐个判断：未登记 → 建 + 登记；已登记 → 跳过 |
| **B · 新成员加入已有项目** | 给已有项目加 Gitee 协作者之后 | 只为**新成员**判断：未登记 → 建 + 登记；已登记 → 跳过 |
| **C · 成员已在别处建过** | A / B 中发现该人已登记 | **不重复建**，仅确认 hact-config 里有他即可 |

> 节点 A 的执行内联在 `init-project` Step 4.5；本手册是其**权威步骤来源**，并额外覆盖节点 B（中途加人，发生在 init-project 之外）和排错。
> 节点 C 不是单独动作——它是 A / B 里"已登记 → 跳过"的那一支，单列出来提醒：**同一个人在第二个项目里不要再建仓**。

---

## 操作步骤（节点 A / B 通用 —— 对每个"未登记"成员执行）

记：组织 `{notes-org}`、成员 Gitee 用户名 `{username}`、管理者 token `{token}`。

### 1. 建私有仓

```bash
curl -X POST "https://gitee.com/api/v5/orgs/{notes-org}/repos" \
  -d "access_token={token}&name=hact-notes-{username}&private=true&auto_init=true"
```

- 成功：返回含 `id` / `full_name`
- 已存在（同名仓已在）：不报错，直接跳到第 2 步（确保协作者 + 登记到位即可）

### 2. 只加本人为 push 协作者

```bash
curl -X PUT "https://gitee.com/api/v5/repos/{notes-org}/hact-notes-{username}/collaborators/{username}" \
  -d "access_token={token}&permission=push"
```

> **关键**：只加本人，**不加任何其他开发者** → 他们对这个仓无读权限。管理者作为 org admin 天然可读，**无需把自己加进去**。

### 3. 初始化 notes.md（可选但推荐，省成员事）

```bash
git clone https://gitee.com/{notes-org}/hact-notes-{username}.git "E:/group-code/hact-notes-{username}"
```

把 `templates/hact-notes/notes.md` 与 `templates/hact-notes/CLAUDE.md` 写入该仓（`{姓名}` 替换为成员名），然后：

```bash
cd "E:/group-code/hact-notes-{username}"
git add notes.md CLAUDE.md && git commit -m "chore: 初始化个人积累仓" && git push
```

> 若跳过此步，成员首次使用时自己用模板建 `notes.md` 也可——但管理者一次初始化更省事、更统一。

### 4. 通知成员

告诉成员：把仓 clone 到本地 `E:\group-code\hact-notes-{username}\`（与项目仓同层）；之后随手记 `[规范]`/`[checklist]`/`[方法论]`/`[心得]`，自己 push。

### 5. 登记到 hact-config

在 `E:\group-code\hact-method\_meta\hact-config.md`：

- 「成员个人积累仓登记表」加一行：

  ```
  | {username} | gitee.com/{notes-org}/hact-notes-{username} | E:\group-code\hact-notes-{username} |
  ```

- 「harvest-notes 收割游标」加一行：

  ```
  | {username} | —（尚未收割） | 0 |
  ```

---

## 验证（建完抽查）

- 成员能 push 自己的仓；**让成员试 clone 别人的 notes 仓应失败**（无读权限）
- 管理者能 clone / 读所有 notes 仓（org admin 身份）
- hact-config 登记表与组织里实际的 `hact-notes-*` 仓**一一对应**，无遗漏、无多余

---

## 常见失败

| 现象 | 原因 / 处理 |
|---|---|
| 建仓返回 403 | token 对 `{notes-org}` 无建仓权限，或管理者不是组织成员 |
| 加协作者"用户不存在" | `{username}` 拼写错，或对方还没注册 Gitee |
| 成员能看到别人的 notes | 误把别人加成了协作者，或仓没设 `private` —— 核对仓可见性与协作者列表 |
| harvest-notes 漏掉某人 | 该成员建了仓但忘了登记进 hact-config —— 补登记 |

---

## 与收割的衔接

建好并登记后，成员积累的 `[规范]`/`[checklist]`/`[方法论]` 由管理者跑 `harvest-notes` 按登记表遍历、去重择优、上提到公共层（`templates/standards`、`templates/checklists`、方法论待议）；`[心得]` 永不上提。详见 `specs-execution/harvest-notes.md`。

---

## 成员离开（可选）

notes 是个人资产。成员离开团队时，仓可保留（归档）或移交，**不强制删除**；若不再收割，从 hact-config 登记表移除该行即可（`harvest-notes` 据表遍历，移除后自然不再收割）。
