# 任务速查表

> 13 种任务类型一览。遇到"我要做 XX"时，对照这张表找对应任务，在正确的工作区开 CC 会话。

---

## 按场景找任务

| 我想做的事 | 对应任务 |
|-----------|---------|
| 新建一个项目 | `init-project` |
| 写本期产品需求 | `draft-prd-vN` |
| 做技术方案 | `draft-tech-design` |
| 把技术方案拆成开发任务 | `plan-sprint` |
| 认领开发任务、写代码 | `develop-sprint`（sprint）/ `develop-repair`（联调·验收修复）/ `develop-b`（bug·优化） |
| 审查 PR | `pr-review` |
| sprint 全部合并，要联调 | `generate-integration-tests` |
| 联调通过，要人工验收 | `manual-test` |
| 验收通过，要上线 | `deploy` |
| 关闭本期迭代 | `wrap-up-iteration` |
| 收到 bug 报告或优化需求 | `dispatch-new` → `develop-b` |
| 文档与实现对不上 | `revise-doc` |
| 收割成员积累、上提公共规范 | `harvest-notes` |

---

## A 类主线任务（有 Gate）

| 任务 | 做什么 | Gate | 工作区 |
|------|--------|:----:|--------|
| `draft-prd-vN` | 写 PRD，含用户故事和验收标准（AC） | G1 | 项目根 |
| `draft-tech-design` | 写 TRD（接口+数据结构）+ 三份开发规范 | G2 | 项目根 |
| `plan-sprint` | 从 TRD 拆任务包，写入 queue | G3 | 项目根 |
| `develop-sprint` | 认领 sprint 任务包，写代码，创建 PR（拾取前置 G3） | — | 项目根 |
| `develop-repair` | 联调/验收失败的派生修复任务（无 Gate） | — | 项目根 |
| `pr-review` | 对照规范审查 PR，通过后合并 | — | 项目根 |
| `generate-integration-tests` | 写联调脚本，跑测试，失败转修复任务 | — | 项目根 |
| `manual-test` | 人工逐条验收 PRD 验收标准 | G4 | 项目根 |
| `deploy` | SSH 连服务器，构建部署，健康检查 | — | 项目根 |
| `wrap-up-iteration` | 偏离对账 + feedback 分流 + 更新 project.md | G5 | 项目根 |

---

## B 类任务（无 Gate，随时可开始）

| 任务 | 做什么 | 工作区 |
|------|--------|--------|
| `dispatch-new` | 收到 bug/优化需求，判定 B/A 类，写任务包入 b-queue | 项目根 |
| `develop-b`（source=bug/optimization） | 认领 B 类任务包，修复 / 优化，创建 PR | 项目根 |

---

## 支线任务（按需触发）

| 任务 | 触发时机 | 做什么 | 工作区 |
|------|---------|--------|--------|
| `init-project` | 新建项目 | 创建目录、git init、注册 hact-app + Webhook、登记成员 notes 仓 | hact-method |
| `revise-doc` | 文档与实现不符，或用户主动要修订 | 最小化修订 PRD/TRD/standards，通知下游 | 项目根 |
| `harvest-notes` | 成员攒了一批个人积累、或定期 | 只读收割成员 notes，去重择优上提公共层 | hact-method |

> **个人积累（hact-notes）**：每人一个私有仓 `hact-notes-{名}`，随手记 `[规范]`/`[checklist]`/`[方法论]`/`[心得]`。前三类由 `harvest-notes` 上提为团队公共规范；`[心得]` 私有不上提。开发者只 push 自己的 notes 仓，不碰 hact-method。

## develop 家族：source 选壳一览

develop 拆成三个壳（`develop-sprint` / `develop-repair` / `develop-b`），共享实现核心 `develop-core.md`（Step 1–8），由 `source` 选壳：

| source | task.type（壳） | 来自哪个任务 | 说明 |
|--------|----------------|------------|------|
| `sprint` | `develop-sprint` | `plan-sprint` | A 类迭代的正常开发任务（拾取前置 G3，有单/批量会话） |
| `integration` | `develop-repair` | `generate-integration-tests` | 联调失败后的修复任务 |
| `manual-test` | `develop-repair` | `manual-test` | 验收失败后的修复任务 |
| `bug` | `develop-b` | `dispatch-new` | B 类 bug 修复（就地分流，无 wrap-up） |
| `optimization` | `develop-b` | `dispatch-new` | B 类功能优化（同上） |

---

## Gate 一览

| Gate | 由哪个任务签 | 含义 |
|------|------------|------|
| G1 | `draft-prd-vN` | PRD 已确认，授权进入技术设计 |
| G2 | `draft-tech-design` | 技术方案已确认，授权拆 sprint |
| G3 | `plan-sprint` | 开发包就绪，授权开始开发 |
| G4 | `manual-test` | 验收通过，授权部署 |
| G5 | `wrap-up-iteration` | 迭代正式关闭，可启动下一期 |

## 工作区说明

| 工作区 | 路径 | 用途 |
|--------|------|------|
| **项目根** | `E:\group-code\{项目名}\` | 所有开发 / 协调任务 |
| **hact-method** | `E:\group-code\hact-method\` | `init-project`、`harvest-notes` 收割、方法论调整 |
