# 核心概念

HACT 按当前任务协作：Task 定义工作目标与完成条件，模型在已确认事实和授权内推导实现；不要求用户扮演流程角色。

项目工作默认可在 Codex 内完成需求、设计、规划、执行和真实验证，ChatGPT Work 按需使用。用户作必要取舍、Gate 与体验决定；仅真实跨入口搬运稳定文件和短交接指令，不维护 AI 的中间过程。聊天草稿不自动成为项目事实；跨环境交接绑定明确 Git snapshot，入口不赋予批准或验收权限。

项目根保存本项目代码、契约与状态；方法论仓保存公共方法及模板。个人笔记可选，只在获许可且用户明确要求时整理，不作为开发或收尾前置。

## 工作从哪里开始

- 用户已明确工作时，按项目入口加载对应 Task，不预读全部规范；当前 Catalog 和 Task Contract 在 [tasks/](../tasks/README.md)。
- A 类正常迭代的用户操作见 [一期完整流程](02-一期完整流程.md)；bug/局部优化先按 [B Intake](../protocols/b-intake.md) 调查，诊断不等于实施授权。
- `status.yml` 是动态状态入口，sprint 是规划；登记为“可取”仍须核当前前置。状态含义见 [State Protocol](../protocols/state.md)，字段见 [status contract](../skeleton/07-status-contract.md)。
- Task 完成与 Gate 批准分开，用户对同一有效 snapshot 的决定不重复确认；具体边界见 [Gate Protocol](../protocols/gates.md)。

运行时从当前 Task 所需权威输入建立上下文，历史按需查证。项目启动与按需加载使用 `templates/AGENTS.md` 和 `templates/boot-protocol.md`；本文是人类导读，不维护另一份任务清单或执行规则。
