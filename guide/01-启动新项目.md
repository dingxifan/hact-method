# 情境：启动一个新项目

> 适用于：第一次为一个新项目建立工作环境。完成后，团队可以开始写 PRD。

---

## 这个阶段做什么

建立项目的"地基"：本地目录结构、初始配置文件、Gitee 远端仓库、hact-app 项目注册。

完成后，项目就进入可操作状态——有地方放文件，有看板可以看，可以开始写 PRD。

**AI 做 / 你做**

| AI（CC）做 | 你做（需要手动） |
|---|---|
| 创建完整本地目录结构和初始文件 | 说清楚项目叫什么、大致做什么 |
| git init + 首次 commit + git push | **在 Gitee 手动创建空仓库**，把地址告诉 CC |
| 自动注册 hact-app + 配置 Gitee Webhook | 提供 hact-app 地址和 CC Token（一次性） |

---

## 步骤

### 第一步：告诉 CC 要新建一个项目

打开 `hact-method` 目录，启动新 CC 会话，直接描述就好，不用套格式。比如：

> "我要新建一个项目，叫 hact-app，是一个给团队用的协作看板工具。"

CC 会明白这是在立项，引导你一步步完成。它会在 `E:\group-code\{项目名}\` 创建以下结构：

```
{项目名}/
├── iterations/
│   └── v1/
│       └── queue/              ← 任务包放这里（plan-sprint 后由 CC 填充）
│           └── done/
├── _meta/
│   ├── input/                  ← 背景材料、上下文文档
│   └── sessions/               ← 跨会话接续文件
├── .claude/
│   └── commands/
│       └── gitee-ops.md        ← /gitee-ops Gitee 仓库操作命令
├── project.md                  ← 跨迭代项目快照
├── decisions.md                ← 架构决策记录
├── design.md                   ← 视觉规格
├── reusables.md                ← 可复用资产
├── backlog.md                  ← 积压与偏离
├── feedback.md                 ← 各阶段反馈
├── b-tasks.md                  ← B 类任务总账
└── CLAUDE.md                   ← 引用 hact-method 规范
```

> `prd.md`、`trd.md`、`gates.md` 等文件不是占位创建的，而是由后续各任务运行时生成：写 PRD 时才有 `prd.md`，写技术方案时才有 `trd.md`，以此类推。

### 第二步：在 Gitee 手动创建空仓库

这一步需要你自己操作：去 Gitee 新建一个仓库，**不要勾选"初始化仓库"**（保持空仓库），然后把仓库地址告诉 CC（格式如 `https://gitee.com/{你的账号}/{项目名}.git`）。

CC 拿到地址后会自动完成剩余工作：绑定远端、首次推送。

### 第三步：CC 自动完成 hact-app 注册和 Webhook 配置

这一步 CC 会自动做完，不需要手动操作。CC 会：

1. 生成一个随机 Webhook secret
2. 调用 hact-app 接口，把项目注册进去
3. 调用 Gitee API，在仓库里配置好 Webhook

CC 需要你提供两个信息（**一次性配置，之后新建项目不用再填**）：
- hact-app 的部署地址（如 `https://hact.example.com`）
- CC Token（服务器环境变量里的 `CC_TOKEN` 值）

提供后，CC 会一次性跑完，后续新项目直接复用，不再询问。

### 第四步：验证同步正常

CC 会推一个空 commit，然后查询 sync_event 接口，确认有 `success` 或 `skipped` 记录。

**不要只看项目列表有没有出现**——项目注册时就会出现在列表里，那不能说明 webhook 通了。必须有 sync_event 记录才能确认 Gitee → hact-app 链路真正打通。`status=failed` 或无记录意味着 webhook token 配置有问题，必须在此步修复，不能带病进入后续流程。

---

## 完成标志

- [ ] 本地目录结构完整
- [ ] 推送到 Gitee，远端仓库可见
- [ ] hact-app 项目注册完成，Webhook 可用
- [ ] 团队成员权限配置完毕

完成后，进入下一步：[一期完整流程](02-一期完整流程.md)，开始写 PRD。

---

## hact-app 里此时能看到

项目出现在项目列表，Gate 全部未签（灰色），迭代 v1 已创建，开发者看板空白——这是正确状态，说明地基就绪。
