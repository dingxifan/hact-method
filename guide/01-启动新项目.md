# 情境：启动一个新项目

> 适用于：第一次为一个新项目建立工作环境。完成后，团队可以开始写 PRD。

---

## 这个阶段做什么

建立项目的"地基"：本地目录结构、初始配置文件、Gitee 远端仓库、连接与凭据登记、项目共识讨论（填地基蓝图）。

完成后，项目就进入可操作状态——有地方放文件，地基蓝图已立，可以开始走 V0 或写 PRD。

**AI 做 / 你做**

| AI（CC）做 | 你做（需要手动） |
|---|---|
| 创建完整本地目录结构和初始文件 | 说清楚项目叫什么、大致做什么 |
| git init + 首次 commit + git push | **在 Gitee 手动创建空仓库**，把地址告诉 CC |
| 播种 `connections.yml` + 校验连接凭据 | 首次配置时提供 Gitee Token（一次性，落 `~/.hact/secrets.env`） |
| 引导项目共识讨论、填 `foundation.md` | 讲清楚项目全貌与核心实体 |

---

## 步骤

### 第一步：告诉 CC 要新建一个项目

打开 `hact-method` 目录，启动新 CC 会话，直接描述就好，不用套格式。比如：

> "我要新建一个项目，叫 mail-ai，是一个给团队用的邮件协作工具。"

CC 会明白这是在立项，引导你一步步完成。它会在与方法论仓同级的 `{工作区根}/{项目名}/` 创建以下结构：

```
{项目名}/
├── iterations/
│   └── v1/
│       └── queue/              ← 任务包放这里（plan-sprint 后由 CC 填充）
│           └── done/
├── _meta/
│   ├── input/                  ← 背景材料、上下文文档
│   └── sessions/               ← 跨会话接续文件
├── .claude/
│   └── commands/
│       └── gitee-ops.md        ← /gitee-ops Gitee 仓库操作命令
├── project.md                  ← 跨迭代项目快照
├── decisions.md                ← 架构决策记录
├── design.md                   ← 视觉规格
├── reusables.md                ← 可复用资产
├── backlog.md                  ← 积压与偏离
├── feedback.md                 ← 各阶段反馈
├── b-tasks.md                  ← B 类任务总账
└── CLAUDE.md                   ← 引用 hact-method 规范
```

> `prd.md`、`trd.md`、`gates.md` 等文件不是占位创建的，而是由后续各任务运行时生成：写 PRD 时才有 `prd.md`，写技术方案时才有 `trd.md`，以此类推。

### 第二步：在 Gitee 手动创建空仓库

这一步需要你自己操作：去 Gitee 新建一个仓库，**不要勾选"初始化仓库"**（保持空仓库），然后把仓库地址告诉 CC（格式如 `https://gitee.com/{你的账号}/{项目名}.git`）。

CC 拿到地址后会自动完成剩余工作：绑定远端、首次推送。

---

## 完成标志

- [ ] 本地目录结构完整
- [ ] 推送到 Gitee，远端仓库可见
- [ ] `connections.yml` 已播种，`node scripts/check-conn.js check` 通过
- [ ] `foundation.md` 领域地图与地基关注点已填
- [ ] 团队成员权限配置完毕

完成后，进入下一步：[一期完整流程](02-一期完整流程.md)，开始写 PRD。
