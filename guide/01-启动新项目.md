# 情境：启动一个新项目

适用于首次建立项目；完整契约见 [init-project](../tasks/init-project.md)。已有仓库接入当前 Method 先按 [旧项目接入指南](08-旧项目全面接入新版.md)，不覆盖现有内容或恢复旧入口。

## 你提供什么

在方法论工作区向 Codex 描述项目名称、用途、核心实体和重要约束，例如“新建 mail-ai，供团队协作处理邮件”。确认 repository identity、远端/协作范围及必要授权；V0 走/跳和真实业务歧义由用户决定，不逐项确认 mkdir、复制等机械步骤。

远端可以采用 Gitee、GitHub 或其他项目选定 provider，不把 Gitee 手工操作当作所有项目的前置。Codex 只在已授权能力内创建或绑定远端；需要用户操作时说明具体缺口。已有 remote 先核实际状态，不能直接覆盖。

例如用户选择 Gitee 且需手动建新仓时，可创建不带初始化内容的空仓并提供地址；这只是 provider 路径示例，不是额外人工确认点。凭据留当前安全 credential mechanism，仅在有需要时配置，不能写进 Git 或持久化聊天；`connections.yml` 只存坐标与 secret reference。

## Codex 完成什么

从官方 Accepted main 解析本次固定 Method SHA，按该版本 Task/模板创建独立项目目录、Git、当前入口与检查器、连接配置及必要项目事实；完成实际验证和已授权交付。`prd.md`、`trd.md` 等由后续 Task 产生，不为了目录齐全提前造设计内容。初始化真实核 hook/guard 与 tracked source 是否对齐，不以文件存在宣称生效，也不覆盖项目已有检查。后续新工作通过统一启动入口检查更新，自动隔离试升级，流程见 `07-同步方法论.md`。

项目共识写入 Foundation seed，只有稳定、跨切面、晚建代价高的约束才考虑 V0。选择 V0 时先完成对应 Foundation 路径，否则进入 PRD；不默认增建前期能力。

## 完成与接续

- 实际目录、入口/角色配置与必要模板齐备，项目 `check-codex-project` 通过。
- `connections.yml` 与适用连接检查、项目所需 guard/checker 验证满足 Task 要求。
- Foundation 共识、V0/V1+ 路由及必要协作权限明确。
- immutable remote Git truth 与任务所需交付已建立并核验，未完成能力或授权如实报告。

这些只是导读，所有初始化产物、conditional review 与完成条件以 Task Contract 为准，不以此短表代替。后续参照 [一期完整流程](02-一期完整流程.md)；没有 Gate 与 init-project 绑定。
